In this lecture, we will discuss the concept of **dropped iterations** in k6 scenarios.

Dropped iterations occur when k6 is unable to start new iterations at the configured rate, usually due to:

- Insufficient system resources  
- Exceeding the maximum number of virtual users (VUs)  
- Backend performance bottlenecks  

Understanding and managing dropped iterations is crucial for accurate load testing and performance analysis.

---

## What are Dropped Iterations?

Dropped iterations refer to scenarios where k6 fails to start new iterations as expected.

This typically happens when:

- The system under test cannot keep up with the desired load  
- k6 cannot create enough virtual users to sustain the configured rate  
- The execution environment becomes a bottleneck  

---

## Why Dropped Iterations Happen

Dropped iterations can occur due to:

### 1. Insufficient Resources

- CPU or memory limitations on the load generator machine  
- Network bandwidth limitations  

When the system cannot generate load fast enough, iterations are skipped.

---

### 2. Exceeding Maximum Virtual Users

- Pre-allocated VUs are not enough  
- k6 hits the `maxVUs` limit  
- No additional VUs can be created to sustain the load  

---

### 3. System Under Test Bottlenecks

- Backend servers are too slow to handle incoming requests  
- Database latency or saturation  
- API response delays affecting iteration scheduling  

---

### 4. Application Performance Issues

- Slow endpoints  
- Blocking operations  
- Inefficient code paths  

These reduce throughput and cause missed iterations.

---

## Example: High Load Scenario

```javascript id="dropped_iterations_example"
import http from "k6/http";
import { sleep } from "k6";

export const options = {
    scenarios: {
        high_rate: {
            executor: "constant-arrival-rate",
            rate: 100, // 100 iterations per second
            timeUnit: "1s",
            duration: "20s",
            preAllocatedVUs: 10,
            maxVUs: 20,
        },
    },
};

export default function () {
    http.get("https://test.k6.io");
    sleep(1);
}
```

---

## What Happens in This Example?

In this scenario:

- k6 tries to execute **100 iterations per second**
- Only **20 VUs maximum** are allowed
- The system cannot keep up with the configured rate

### Result:

- k6 logs a warning about insufficient VUs
- Some iterations are **dropped**
- `dropped_iterations` metric increases

---

## Example Output Behavior

When executed, you may observe:

- Warning: insufficient virtual users
- Maximum VU limit reached
- Dropped iteration count increases significantly

Example:

- 1687 iterations dropped (as seen in heavy load scenarios)

---

## What Dropped Iterations Indicate

Dropped iterations are not just errors — they provide important insights.

---

### 1. Performance Bottlenecks

- System cannot handle intended load
- Indicates saturation points in infrastructure

---

### 2. Resource Limitations

- CPU or memory is insufficient
- Network throughput is constrained

---

### 3. Test Configuration Issues

- Arrival rate too high
- VUs too low for expected load
- Poorly tuned scenario settings

---

### 4. System Scalability Limits

- Shows maximum capacity of the system
- Helps identify breaking points before failure

---

### 5. Test Reliability Impact

- Results may not reflect intended load
- Metrics become less accurate
- Some iterations never executed

---

## Key Takeaway

Dropped iterations mean:

> k6 wanted to execute more iterations than it could actually schedule.

They indicate that either:

- The **load is too high**, or
- The **system cannot handle the expected traffic**, or
- The **test configuration needs adjustment**
