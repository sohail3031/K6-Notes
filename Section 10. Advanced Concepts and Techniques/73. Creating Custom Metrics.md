## What are Custom Metrics?

Custom metrics in k6 allow you to define metrics tailored to your testing needs.

This flexibility helps you track and analyze performance characteristics that are not covered by built-in k6 metrics.

---

## Types of Custom Metrics in k6

k6 provides four main types of custom metrics:

### 1. Counter
- Tracks the total number of occurrences
- Increments over time

---

### 2. Gauge
- Records the value at a specific point in time
- Can increase or decrease

---

### 3. Rate
- Measures the percentage of successful events
- Example: success vs failure ratio

---

### 4. Trend (Focus of this Lecture)

- Collects multiple values over time
- Calculates statistical results such as:
  - Average
  - Minimum / Maximum
  - Median
  - Percentiles (90th, 95th, etc.)
  - Standard deviation

---

## Use Case: Tracking HTTP Waiting Time

We will track:

> `res.timings.waiting`

This represents the time spent waiting for the first byte of the response.

---

## Code Example

```javascript id="k6_custom_metrics_trend"
import http from "k6/http";
import { Trend } from "k6/metrics";

// Create a custom trend metric
const myTrend = new Trend("waiting_time");

export default function () {
    const res = http.get("https://httpbin.test.k6.io");

    // Add waiting time to custom metric
    myTrend.add(res.timings.waiting);

    // Log metric name
    console.log(myTrend.name);
}
```

---

## Explanation

### 1. Import Trend Metric

```javascript
import { Trend } from "k6/metrics";
```

- Used to store and analyze multiple values over time

---

### 2. Create Custom Metric

```javascript
const myTrend = new Trend("waiting_time");
```

- Creates a metric named `waiting_time`
- k6 automatically aggregates statistical data

---

### 3. Collect HTTP Timing Data

```javascript
res.timings.waiting
```

This represents:

- Time spent waiting for server response
- Measured in milliseconds

---

### 4. Add Data to Metric

```javascript
myTrend.add(res.timings.waiting);
```

Each request adds a new data point to the trend.

---

## What Happens During Execution?

When you run the test:

- One virtual user executes one iteration
- HTTP request is sent
- Waiting time is recorded
- Data is stored in `waiting_time` metric

---

## Output Metrics Generated

k6 automatically calculates:

- Average waiting time
- Minimum / Maximum values
- Median
- 90th percentile
- 95th percentile

Example output:

```text
waiting_time
avg=120ms
min=90ms
med=110ms
max=300ms
p(90)=200ms
p(95)=250ms
```

### 2. Deeper Performance Insights

### 3. Statistical Analysis

Identify slow endpoints or inconsistent performance patterns
