## Overview of Open and Closed Models

### Closed Model

In a **closed model**, a fixed number of virtual users (VUs) perform a certain number of iterations.

- Concurrency is fixed
- Each VU completes iterations before moving on
- Load is predictable and controlled

**Best suited for:**
- Internal systems
- Fixed user base applications
- Stress testing with controlled load

---

### Open Model

In an **open model**, new virtual users or iterations are introduced continuously at a specified rate.

- Load is based on arrival rate
- Users are continuously created
- Not dependent on completion of previous iterations

**Best suited for:**
- Public websites
- APIs under real-world traffic
- Systems with continuous user arrivals

---

## Key Difference

| Feature | Open Model | Closed Model |
|--------|------------|--------------|
| Load Type | Arrival-based | Concurrency-based |
| Control | Rate of requests | Number of VUs |
| Behavior | Continuous user arrival | Fixed user pool |
| Predictability | Less predictable | Highly predictable |

---

## Executors in k6

The type of model depends on the **executor** used in scenarios.

### Open Model Executors

- `constant-arrival-rate`
- `ramping-arrival-rate`

### Closed Model Executors

- `per-vu-iterations`
- `constant-vus`
- `ramping-vus`

---

## Configuration Focus

### Open Model

Focus on **request arrival rate**:

- rate
- timeUnit
- duration
- preAllocatedVUs
- maxVUs

---

### Closed Model

Focus on **concurrency and iterations**:

- vus
- iterations
- duration (optional depending on executor)

---

## Pros and Cons

## Open Model

### Advantages

- Realistic traffic simulation
- Easy control over request rate
- Scalable under high load
- Best for throughput testing

### Disadvantages

- Hard to control exact concurrency
- Load can be unpredictable
- More complex performance analysis

---

## Closed Model

### Advantages

- Precise control over number of users
- Predictable load pattern
- Easier result analysis
- Good for stress testing

### Disadvantages

- Less realistic for public traffic
- Not suitable for dynamic workloads
- Limited scalability modeling

## Code Examples

## 1. Open Model Example

```javascript id="open_model_k6"
import http from "k6/http";
import { sleep } from "k6";

export const options = {
    scenarios: {
        open_model: {
            executor: "constant-arrival-rate",
            rate: 5, // 5 iterations per second
            timeUnit: "1s",
            duration: "30s",
            preAllocatedVUs: 5,
            maxVUs: 10,
        },
    },
};

export default function () {
    http.get("https://test.k6.io");
    sleep(1);
}
```

### Behavior

- 5 iterations per second
- New iterations continuously scheduled
- VUs are created dynamically as needed

---

## 2. Closed Model Example

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
    scenarios: {
        closed_model: {
            executor: "per-vu-iterations",
            vus: 5,
            iterations: 10,
        },
    },
};

export default function () {
    http.get("https://test.k6.io");
    sleep(1);
}
```

### Behavior

- 5 virtual users
- Each VU runs 10 iterations
- Total iterations = 50
- Execution is sequential per VU

## Use Cases

## Open Model Use Cases

### 1. Public Web Traffic Simulation

- Real-world user arrival patterns
- Example: News websites during breaking events

### 2. E-commerce Platforms

- Continuous user browsing and purchasing
- Example: Black Friday sales load testing

### 3. API Load Testing

- Constant request flow
- Example: Public APIs under heavy usage

### 4. Streaming Services

- Continuous viewer access
- Example: Video streaming platforms

---

## Closed Model Use Cases

### 1. Internal Applications

- Fixed user base systems
- Example: HR portals

### 2. Stress Testing

- Controlled load for bottleneck detection
- Example: Database stress tests

### 3. Multiplayer Games

- Fixed number of players
- Example: Game server load testing

### 4. SaaS Applications

- Known user workflows
- Example: Project management tools

### 5. Capacity Planning

- Determine system limits under fixed load
- Example: Web server benchmarking
