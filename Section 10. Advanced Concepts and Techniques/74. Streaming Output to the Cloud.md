In this demo, we will differentiate between running a test directly on **k6 Cloud** and **streaming the output of a locally executed test to k6 Cloud**.

We will use a simple k6 script that interacts with the k6 test API to illustrate both approaches.

---

## Two Ways of Using k6 Cloud

### 1. Local Execution + Cloud Streaming
- Script runs on your local machine
- Only results (metrics/output) are sent to the cloud
- Useful for debugging locally while still using cloud dashboards

---

### 2. Full Cloud Execution
- Script is uploaded to k6 Cloud
- Execution happens in cloud infrastructure
- Results are generated and stored in cloud

---

## Key Insight

Regardless of where execution happens:
- Virtual Users (VUs) are always consumed from cloud limits
- Cloud storage and processing are part of usage billing

---

## Basic k6 Test Script

```javascript
import http from "k6/http";
import { check } from "k6";

export const options = {
    vus: 10,
    duration: "30s"
};

export default function () {
    const res = http.get("https://httpbin.test.k6.io/get");

    check(res, {
        "status is 200": (r) => r.status === 200
    });
}
```

---

# Running k6 Scripts (4 Ways)

## 1. Run Locally (No Cloud)

### Command

```bash
k6 run script.js
```

### Behavior

- Execution happens on local machine
- Output is shown only in terminal
- No cloud interaction

---

## 2. Run Locally + Send Output to Cloud

### Command

```bash
k6 run --out cloud script.js
```

### Before Running

Login to k6 Cloud:

```bash
k6 login cloud -t <TOKEN>
```

### Behavior

- Script executes locally
- Metrics are streamed to Grafana Cloud in real time
- Cloud dashboard shows live results

---

## 3. Run Script in Cloud (From Local Code)

### Command

```bash
k6 cloud script.js
```

### Behavior

- Script is uploaded to cloud
- Execution happens in cloud infrastructure
- Results are collected and visualized in cloud

---

## 4. Write and Run Fully in Cloud

### Behavior

- Code is written or managed in Grafana Cloud UI
- Execution happens entirely in cloud
- No local machine required

---

# Comparison Summary

|Mode|Execution Location|Output Location|Use Case|
|---|---|---|---|
|Local|Local machine|Terminal|Debugging|
|Local + Cloud Output|Local machine|Cloud dashboard|Hybrid testing|
|Cloud Run (`k6 cloud`)|Cloud|Cloud|Scalable load testing|
|Cloud Native|Cloud UI|Cloud|Team-based testing|

---

## Key Takeaways

- k6 supports flexible execution models
- You can separate execution and result analysis
- Cloud integration enables advanced reporting and comparison of test runs
- All modes still consume cloud VU limits when applicable
