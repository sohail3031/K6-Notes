This is your **first real WebSocket load testing script in K6**, and it introduces a completely different model compared to HTTP testing.

Let’s break it down clearly so you actually understand what’s happening (not just the code).

## Full Script

```javascript
import { sleep } from 'k6';
import { WebSocket } from 'k6/experimental/websockets';
import { setInterval } from 'k6/timers';
import { Counter } from "k6/metrics";

let BASE_URL = __ENV.BASE_URL || 'http://localhost:3333';
BASE_URL = BASE_URL.replace("https://", "wss://");
BASE_URL = BASE_URL.replace("http://", "ws://");

export const options = {
  scenarios: {
    receiver: {
      exec: "receiver",
      executor: "ramping-vus",
      executor: 'shared-iterations',
      iterations: 1,
      maxDuration: '15s',
    },
    sender: {
      exec: "sender",
      executor: 'shared-iterations',
      iterations: 20,
      vus: 10,
      // delay the start to get the receiver ready
      startTime: '2s',
    },
  }
};

// send two WS messages
export function sender() {
    const ws = new WebSocket(`${BASE_URL}/ws`);

    ws.addEventListener('open', () => {
        ws.send(JSON.stringify({ ws_visitor_id: `VU ${__VU}`, msg: "order_pizza" }));

        sleep(0.2);

        ws.send(JSON.stringify({ ws_visitor_id: `VU ${__VU}`, msg: "pizza_status?" }));

        sleep(0.1);

        ws.close();
    });
}

export function receiver () {
  // Close the WS connection to end the iteration once the number of expected messages is received.
  // Be aware that a local counter (`messageCounter`) is valid here because only one `receiver` iteration runs.
  let messageCounter = 0;
  const totalExpectedMessages = 20*2; // 20 iterations * 2 messages per iteration
  const ws = new WebSocket(`${BASE_URL}/ws`);

  ws.addEventListener('open', () => {
    ws.addEventListener('message', (e) => {
      const msg = JSON.parse(e.data);

      console.log(`VU ${__VU} received: ${msg.ws_visitor_id} msg: ${msg.msg}`);

      messageCounter++;

      if (messageCounter === totalExpectedMessages) {
        ws.close();
      }
    });
  });
}
```

# 🌐 88. WebSockets in K6 (Core Idea)
Unlike HTTP:

| HTTP                  | WebSocket                     |
| --------------------- | ----------------------------- |
| Request → Response    | Persistent connection         |
| Stateless             | Stateful session              |
| Short-lived           | Long-lived                    |
| Client initiates only | Both client + server can send |

So in K6:

> You are no longer testing “requests per second”  
> You are testing “live message flow over time”

---

# 🧠 Big Picture of This Script

You simulate **two independent behaviors**:

### 🟢 1. Sender (traffic generator)

- Opens WebSocket
- Sends messages
- Closes connection

### 🔵 2. Receiver (listener)

- Opens WebSocket
- Listens continuously
- Counts messages
- Closes after receiving expected volume

# ⚠️ Important Observations (Interview-level insight)

## 1. Long-lived connections = expensive

WebSockets:

- keep memory open
- maintain active connections
- simulate real concurrency load

So:

> fewer VUs can generate heavy load

---

## 2. Timing matters

```javascript
startTime: '2s'
```

This ensures:

> receiver is ready BEFORE sender starts

Otherwise:

- messages may be lost
- test becomes invalid

---

## 3. Stateful testing

Unlike HTTP:

- each WS connection is a session
- K6 tracks lifecycle, not just requests

# ⚠️ Subtle issue in script (important)

You have:

```javascript
executor: "ramping-vus",
executor: 'shared-iterations',
```

👉 This is a conflict (only one executor allowed)

Correct structure should be:

```javascript
receiver: {
  executor: 'shared-iterations',
  iterations: 1,
  maxDuration: '15s',
},
```

So in real-world usage:

> this script should be cleaned before production use
