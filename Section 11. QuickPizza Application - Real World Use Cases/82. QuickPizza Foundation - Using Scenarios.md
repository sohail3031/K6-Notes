# 🧪 07. scenarios.js — What this test really does

This script introduces the **most powerful k6 concept: Scenarios**

👉 Instead of one load pattern, you now run **multiple user behaviors in the same test**

## Full Script

```javascript
import http from "k6/http";
import { check, sleep } from "k6";
import { Trend, Counter } from "k6/metrics";
import { textSummary } from "https://jslib.k6.io/k6-summary/0.0.2/index.js";

const BASE_URL = __ENV.BASE_URL || 'http://localhost:3333';

export const options = {
  scenarios: {
    smoke: {
      exec: "getPizza",
      executor: "constant-vus",
      vus: 1,
      duration: "10s",
    },
    stress: {
      exec: "getPizza",
      executor: "ramping-vus",
      stages: [
        { duration: '5s', target: 5 },
        { duration: '10s', target: 5 },
        { duration: '5s', target: 0 },
      ],
      startTime: "10s",
    },
  },
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<500', 'p(99)<1000'],
    quickpizza_ingredients: [{ threshold: 'avg<8', abortOnFail: false }],
    checks: ["rate > 0.95"]
  },
};

const pizzas = new Counter('quickpizza_number_of_pizzas');
const ingredients = new Trend('quickpizza_ingredients');

export function setup() {
  let res = http.get(BASE_URL)

  if (res.status !== 200) {
    throw new Error(`Got unexpected status code ${res.status} when trying to setup. Exiting.`)
  }
}

export function getPizza() {
  let restrictions = {
    maxCaloriesPerSlice: 500,
    mustBeVegetarian: false,
    excludedIngredients: ["pepperoni"],
    excludedTools: ["knife"],
    maxNumberOfToppings: 6,
    minNumberOfToppings: 2
  }
  let res = http.post(`${BASE_URL}/api/pizza`, JSON.stringify(restrictions), {
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'token abcdef0123456789',
    },
  });

  check(res, { "status is 200": (res) => res.status === 200 });

  console.log(`${res.json().pizza.name} (${res.json().pizza.ingredients.length} ingredients)`);

  pizzas.add(1);
  ingredients.add(res.json().pizza.ingredients.length);
  
  sleep(1);
}

export function teardown() {
  // TODO: Send notification to Slack
  console.log("That's all folks!")
}
  
export function handleSummary(data) {
  return {
    'summary.json': JSON.stringify(data, null, 2),
    stdout: textSummary(data, { indent: " ", enableColors: true }),
  }
}
```


---

# 🧠 Core Idea of Scenarios

> A scenario = a separate “user type” or “traffic pattern”

So you are no longer testing:

- one load model ❌

You are testing:

- multiple real-world behaviors together ✅

---

# 🚦 1. Scenario 1 — Smoke Test

```js
smoke: {
  exec: "getPizza",
  executor: "constant-vus",
  vus: 1,
  duration: "10s",
}
```

## What it means:

- 1 virtual user only
- runs continuously for 10 seconds
- calls `getPizza()`

## Purpose:

👉 “Is the system alive?”

This is NOT performance testing.

It is:

- sanity check
- API availability test

---

# 🔥 2. Scenario 2 — Stress Pattern (Ramping Load)

```js
stress: {
  executor: "ramping-vus",
  stages: [
    { duration: '5s', target: 5 },
    { duration: '10s', target: 5 },
    { duration: '5s', target: 0 },
  ],
  startTime: "10s",
}
```

## What happens:

### Timeline:

|Time|Action|
|---|---|
|0–10s|smoke test runs|
|10s|stress test starts|
|10–15s|ramp up to 5 VUs|
|15–25s|steady load|
|25–30s|ramp down|

---

## Purpose:

👉 Simulate real users coming in AFTER system is warmed up

This models:

- traffic bursts
- real usage spikes
- system under load after startup

# 📊 4. Thresholds (Still Active)

Even with scenarios, thresholds apply globally:

```js
http_req_failed: ['rate<0.01']
http_req_duration: ['p(95)<500', 'p(99)<1000']
checks: ["rate > 0.95"]
```

## Meaning:

|Rule|Meaning|
|---|---|
|<1% failures|system reliability|
|p95 < 500ms|most requests fast|
|p99 < 1s|worst-case still acceptable|
|checks > 95%|business logic stable|
