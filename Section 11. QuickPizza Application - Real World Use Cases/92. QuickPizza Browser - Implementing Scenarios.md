Welcome to this lecture on using **multiple scenarios with thresholds** in k6 browser testing.

This builds on earlier concepts and demonstrates how to simulate **different user journeys simultaneously** within a single performance test.

## Full Script

```javascript
import { browser } from "k6/browser";
import { check } from 'https://jslib.k6.io/k6-utils/1.5.0/index.js';

const BASE_URL = __ENV.BASE_URL || "http://localhost:3333";

export const options = {
  scenarios: {
    pizzaRecommendations: {
      executor: "shared-iterations",
      options: {
        browser: {
          type: "chromium",
        },
      },
      exec: "pizzaRecommendations",
    },
    admin: {
      executor: "shared-iterations",
      options: {
        browser: {
          type: "chromium",
        },
      },
      exec: "admin",
    },
  },
  thresholds: {
    browser_web_vital_fcp: ["p(95) < 3000"],
    browser_web_vital_lcp: ["p(95) < 4000"],
  },
};

export async function admin() {
  let checkData;
  const page = await browser.newPage();

  try {
    await page.goto(`${BASE_URL}/admin`, { waitUntil: "networkidle" });
    await page.getByRole("button", { name: "Sign in" }).click();

    checkData = await page.getByRole("button", { name: "Logout" }).textContent();

    check(checkData, {
      "logout button text": checkData == "Logout",
    });
  } finally {
    await page.close();
  }
}

export async function pizzaRecommendations() {
  let checkData;
  const page = await browser.newPage();

  try {
    await page.goto(BASE_URL);
    
    checkData = await page.locator("h1").textContent();

    check(checkData, {
      header: checkData == "Looking to break out of your pizza routine?",
    });

    await page.getByRole("button", { name: "Pizza, Please!" }).click();
    await page.waitForTimeout(500);
    await page.screenshot({ path: "screenshot.png" });

    checkData = await page.locator("div#recommendations").textContent();

    check(checkData, {
      recommendation: checkData != "",
    });
  } finally {
    await page.close();
  }
}
```

---

## **What this script demonstrates**

This test runs two independent browser scenarios:

### 🔹 1. pizzaRecommendations scenario

Simulates a **normal user journey**

- Opens homepage
- Checks header
- Clicks “Pizza, Please!”
- Captures screenshot
- Validates recommendations section

---

### 🔹 2. admin scenario

Simulates an **admin user journey**

- Opens admin page
- Clicks “Sign in”
- Validates “Logout” button appears

## **Scenario configuration**

```javascript
export const options = {
  scenarios: {
    pizzaRecommendations: {
      executor: "shared-iterations",
      options: {
        browser: { type: "chromium" },
      },
      exec: "pizzaRecommendations",
    },
    admin: {
      executor: "shared-iterations",
      options: {
        browser: { type: "chromium" },
      },
      exec: "admin",
    },
  },
};
```

---

## **Key concept: Multiple scenarios**

Each scenario:

- Runs independently
- Has its own function (`exec`)
- Uses its own browser instance
- Executes concurrently

This allows simulation of real-world usage patterns like:

- Normal users browsing the app
- Admin users managing the system
- Both happening at the same time

---

## **Browser performance thresholds**

```javascript
thresholds: {
  browser_web_vital_fcp: ["p(95) < 3000"],
  browser_web_vital_lcp: ["p(95) < 4000"],
}
```

### What this means:

- **FCP (First Contentful Paint)** must be under 3 seconds (95th percentile)
- **LCP (Largest Contentful Paint)** must be under 4 seconds (95th percentile)

These thresholds apply across **both scenarios combined**.

## **Why async functions are used**

Both scenarios are defined as:

```javascript
export async function pizzaRecommendations() {}
export async function admin() {}
```

Because:

- Browser operations are asynchronous
- Multiple virtual users may run them simultaneously
- Each scenario executes independently

---

## **Execution behavior**

When the test runs:

- Both scenarios start **concurrently**
- Each uses its own virtual users
- Metrics are collected together
- Thresholds apply globally

---

## **What k6 measures**

Across both scenarios, k6 collects:

### 📊 Core Web Vitals

- FCP
- LCP
- CLS (if applicable)
- INP (interaction metrics)

### 📊 Scenario-level metrics

- Execution time per scenario
- Check success rate
- Browser resource usage

## **Key insight**

> Scenarios allow you to simulate **real-world user behavior diversity** in a single test.

Instead of testing one flow at a time, you test:

- Customer journeys
- Admin workflows
- System behavior under combined load
