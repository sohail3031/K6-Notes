## Concept: Load Stages in k6

Stages allow you to simulate **gradual changes in traffic**.

Instead of a constant load, you can model:

- Ramp-up traffic
- Steady-state traffic
- Ramp-down traffic

This is closer to real-world usage patterns.

---

## Test Script Overview

We simulate API calls to:

```text
/api/pizza
```

with varying load stages.

---

## Code Explanation

### Full Script

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

const BASE_URL = __ENV.BASE_URL || "http://localhost:3333";

export const options = {
    stages: [
        { duration: "5s", target: 5 },  // Ramp-up to 5 VUs
        { duration: "10s", target: 5 }, // Stay at 5 VUs
        { duration: "5s", target: 0 },  // Ramp-down to 0
    ],
};

export default function () {

    let restrictions = {
        maxCaloriesPerSlice: 500,
        mustBeVegetarian: false,
        excludedIngredients: ["pepperoni"],
        excludedTools: ["knife"],
        maxNumberOfToppings: 6,
        minNumberOfToppings: 2
    };

    let res = http.post(
        `${BASE_URL}/api/pizza`,
        JSON.stringify(restrictions),
        {
            headers: {
                "Content-Type": "application/json",
                "Authorization": "token abcdef0123456789",
            },
        }
    );

    check(res, {
        "status is 200": (r) => r.status === 200,
    });

    console.log(
        `${res.json().pizza.name} (${res.json().pizza.ingredients.length} ingredients)`
    );

    sleep(1);
}
```

---

## Load Stages Breakdown

### Stage 1: Ramp-Up

```text
duration: 5s
target: 5 VUs
```

- Gradually increases load from 0 → 5 users
- Simulates increasing traffic

---

### Stage 2: Steady State

```text
duration: 10s
target: 5 VUs
```

- Maintains constant load
- Simulates normal system usage

---

### Stage 3: Ramp-Down

```text
duration: 5s
target: 0 VUs
```

- Gradually reduces load to zero
- Simulates users leaving the system

---

## What Happens During Execution?

1. k6 starts with 0 virtual users
2. Users ramp up to 5 over 5 seconds
3. Load stabilizes for 10 seconds
4. Users ramp down to 0 over 5 seconds
5. Each VU sends POST requests to `/api/pizza`
6. Responses are validated and logged
