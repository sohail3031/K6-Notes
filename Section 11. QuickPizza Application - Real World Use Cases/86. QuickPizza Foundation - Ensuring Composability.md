## 🧩 What “Composability” means in K6

Composability = designing your load test as **independent, reusable building blocks** instead of one monolithic script.

### Full Script

```javascript
import http from "k6/http";
import { check, sleep } from "k6";
import { Trend, Counter } from "k6/metrics";
import { textSummary } from "https://jslib.k6.io/k6-summary/0.0.2/index.js";
import { SharedArray } from "k6/data";
import { browser } from "k6/browser";

const BASE_URL = __ENV.BASE_URL || "http://localhost:3333";

export const options = {
  scenarios: {
    smoke: {
      exec: "getPizza",
      executor: "constant-vus",
      vus: 1,
      duration: "10s",
    },
    stress: {
      exec: "getPizza",
      executor: "ramping-vus",
      stages: [
        { duration: "5s", target: 5 },
        { duration: "10s", target: 5 },
        { duration: "5s", target: 0 },
      ],
      startTime: "10s",
    },
    browser: {
      exec: "checkFrontend",
      executor: "constant-vus",
      vus: 1,
      duration: "15s",
      options: {
        browser: {
          type: "chromium",
        },
      },
    },
  },
  thresholds: {
    http_req_failed: ["rate<0.01"],
    http_req_duration: ["p(95)<500", "p(99)<1000"],
    quickpizza_ingredients: [{ threshold: "avg<8", abortOnFail: false }],
    checks: ["rate > 0.95"],
  },
};

const pizzas = new Counter("quickpizza_number_of_pizzas");
const ingredients = new Trend("quickpizza_ingredients");
const tokens = new SharedArray("all tokens", function () {
  return JSON.parse(open("./data/tokens.json")).tokens;
});

export function setup() {
  let res = http.get(BASE_URL);

  if (res.status !== 200) {
    throw new Error(
      `Got unexpected status code ${res.status} when trying to setup. Exiting.`
    );
  }
}

export function getPizza() {
  let restrictions = {
    maxCaloriesPerSlice: 500,
    mustBeVegetarian: false,
    excludedIngredients: ["pepperoni"],
    excludedTools: ["knife"],
    maxNumberOfToppings: 6,
    minNumberOfToppings: 2,
  };
  let res = http.post(`${BASE_URL}/api/pizza`, JSON.stringify(restrictions), {
    headers: {
      "Content-Type": "application/json",
      "Authorization": "Token " + tokens[Math.floor(Math.random() * tokens.length)],
    },
  });

  check(res, { "status is 200": (res) => res.status === 200 });

  console.log(
    `${res.json().pizza.name} (${
      res.json().pizza.ingredients.length
    } ingredients)`
  );

  pizzas.add(1);
  ingredients.add(res.json().pizza.ingredients.length);

  sleep(1);
}

export async function checkFrontend() {
  let checkData;
  const page = await browser.newPage();
  
  try {
    await page.goto(BASE_URL);
    
    checkData = await page.locator("h1").textContent();
    
    check(page, {
      header: checkData == "Looking to break out of your pizza routine?",
    });

    await page.locator('//button[. = "Pizza, Please!"]').click();
    await page.waitForTimeout(500);
    await page.screenshot({ path: "screenshot.png" });

    checkData = await page.locator("div#recommendations").textContent();
    
    check(page, {
      recommendation: checkData != "",
    });
  } finally {
    await page.close();
  }
}

export function teardown() {
  // TODO: Send notification to Slack
  console.log("That's all folks!");
}

export function handleSummary(data) {
  return {
    "summary.json": JSON.stringify(data, null, 2),
    stdout: textSummary(data, { indent: " ", enableColors: true }),
  };
}
```

In this script, the test is split into **three independent scenarios**:

### 1. 🧪 Smoke test (basic validation)

- 1 VU
- 10 seconds
- Executes `getPizza()`
- Purpose: sanity check API is alive

---

### 2. 🔥 Stress test (backend load)

- 1 → 5 VUs ramping
- Runs after smoke test (`startTime: "10s"`)
- Same function: `getPizza()`
- Purpose: backend performance under load

---

### 3. 🌐 Browser test (frontend performance)

- Uses `k6/browser` (Chromium)
- Runs `checkFrontend()`
- Purpose: simulate real user interaction

---

## 🧠 Key idea: same system, multiple perspectives

This is the real takeaway:

|Layer|What is tested|Function|
|---|---|---|
|API|backend correctness + load|`getPizza()`|
|Load model|traffic behavior|smoke + stress scenarios|
|UI|real user journey|`checkFrontend()`|

So you're no longer just doing API testing — you're doing **full-stack performance testing**.

## 📊 Why this is powerful

Now K6 is not just load testing APIs — it is also measuring:

### Backend metrics

- response time (p95, p99)
- failure rate
- custom metrics (pizzas, ingredients)

### Frontend metrics (browser)

- page load behavior
- DOM interaction timing
- rendering + UI updates
- navigation latency

## 🧠 What “composability” gives you

Instead of a single test, you now have:

### ✔ Modular structure

- API load test (`getPizza`)
- UI test (`checkFrontend`)
- multiple scenarios independently configured

### ✔ Real-world simulation

- smoke → stress → real user browsing
- matches production traffic patterns

### ✔ Better debugging

If something fails:

- API issue? → backend scenario
- UI issue? → browser scenario
- load issue? → stress scenario

---

## ⚠ One subtle but important concept

### Browser testing runs separately

This block:

```js
browser: {
  type: "chromium"
}
```

means:

- it launches a real browser engine
- heavier than API tests
- consumes more VUs per iteration

So in real-world usage:

> Browser tests are usually kept small (smoke-level), not heavy load tests.
