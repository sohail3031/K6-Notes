Thresholds are how k6 answers a very important question:

> ❓ “Did the system pass or fail this performance test?”

Instead of just collecting metrics, thresholds turn them into **PASS/FAIL rules**.

---

## Full Script

```javascript
import http from "k6/http";
import { check, sleep } from "k6";
import { Trend, Counter } from "k6/metrics";

const BASE_URL = __ENV.BASE_URL || 'http://localhost:3333';

export const options = {
  stages: [
    { duration: '5s', target: 5 },
    { duration: '10s', target: 5 },
    { duration: '5s', target: 0 },
  ],
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<500', 'p(99)<1000'],
    quickpizza_ingredients: [{ threshold: 'avg<8', abortOnFail: false }],
  },
};

const pizzas = new Counter('quickpizza_number_of_pizzas');
const ingredients = new Trend('quickpizza_ingredients');

export function setup() {
  let res = http.get(BASE_URL)

  if (res.status !== 200) {
    throw new Error(`Got unexpected status code ${res.status} when trying to setup. Exiting.`)
  }
}

export default function () {
  let restrictions = {
    maxCaloriesPerSlice: 500,
    mustBeVegetarian: false,
    excludedIngredients: ["pepperoni"],
    excludedTools: ["knife"],
    maxNumberOfToppings: 6,
    minNumberOfToppings: 2
  }
  let res = http.post(`${BASE_URL}/api/pizza`, JSON.stringify(restrictions), {
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'token abcdef0123456789',
    },
  });
  
  check(res, { "status is 200": (res) => res.status === 200 });
  
  console.log(`${res.json().pizza.name} (${res.json().pizza.ingredients.length} ingredients)`);

  pizzas.add(1);
  ingredients.add(res.json().pizza.ingredients.length);

  sleep(1);
}

export function teardown(){
  // TODO: Send notification to Slack
  console.log("That's all folks!")
}
```

# 🧠 1. Where thresholds are defined

In your script:

```javascript
export const options = {
  stages: [
    { duration: '5s', target: 5 },
    { duration: '10s', target: 5 },
    { duration: '5s', target: 0 },
  ],
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<500', 'p(99)<1000'],
    quickpizza_ingredients: [{ threshold: 'avg<8', abortOnFail: false }],
  },
};
```

---

# 📊 2. Understanding each threshold

## 🔴 1. HTTP failure rate

```javascript
http_req_failed: ['rate<0.01']
```

### Meaning:

- Less than **1% requests can fail**

✔ Example:

- 1000 requests → max 10 failures allowed

---

## ⏱️ 2. Response time thresholds

```javascript
http_req_duration: ['p(95)<500', 'p(99)<1000']
```

### Meaning:

|Metric|Requirement|
|---|---|
|p95|< 500 ms|
|p99|< 1000 ms|

### Interpretation:

- 95% of requests must be very fast
- 99% must still stay under 1 second

---

## 🍕 3. Custom metric threshold

```javascript
quickpizza_ingredients: [{ threshold: 'avg<8', abortOnFail: false }]
```

### Meaning:

- Average ingredients per pizza must be < 8

---

### Why this matters:

You are now testing **business rules**, not just performance.

---

# 🧠 3. What `abortOnFail: false` means

```javascript
abortOnFail: false
```

### Meaning:

- Even if threshold fails → test continues

---

### If it were `true`:

- Test stops immediately on failure

---

# 🔄 4. Full execution flow

## Step 1 — Setup

```javascript
http.get(BASE_URL)
```

✔ Ensures API is alive before load begins

---

## Step 2 — Load test execution

Each virtual user:

### 1. Sends pizza request

```javascript
http.post("/api/pizza")
```

### 2. Validates response

```javascript
check(res, { "status is 200": ... })
```

### 3. Extracts data

```javascript
res.json().pizza.ingredients.length
```

### 4. Records metrics

```javascript
pizzas.add(1);
ingredients.add(...)
```

---

## Step 3 — Teardown

```javascript
console.log("That's all folks!")
```

---

# 📊 5. What k6 evaluates after test ends

After execution, k6 checks:

## 🔴 A. HTTP failures

```text
FAIL if rate >= 1%
```

---

## ⏱️ B. Performance SLA

```text
FAIL if:
p95 >= 500ms
OR
p99 >= 1000ms
```

---

## 🍕 C. Business rule validation

```text
FAIL if avg ingredients >= 8
```

---

# 📉 6. Why thresholds are powerful

Without thresholds:

- You only “observe” performance

With thresholds:

- You **enforce performance SLAs**

---

# 🧩 7. Real-world mapping

## Example production SLAs:

|Metric|Real-world meaning|
|---|---|
|p95 < 500ms|Most users get fast response|
|error rate < 1%|System is stable|
|custom metric avg < X|Business logic is healthy|

---

# 🚨 8. What happens when thresholds fail

k6 will:

- Mark test as ❌ FAILED
- Show detailed report
- Optionally abort test (if configured)

---

# 🧠 9. Key takeaway

👉 Thresholds turn k6 from:

> “a load generator”

into:

> “an automated performance gatekeeper”
