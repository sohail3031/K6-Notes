Welcome to this lecture on understanding the **k6 test lifecycle**.

In this session, we will explore how k6 structures tests into three main phases:

- `setup`
- `default` (execution)
- `teardown`

These phases help organize performance tests in a clean and maintainable way.

---

## k6 Test Lifecycle Overview

A k6 test is executed in three stages:

### 1. Setup Phase
Runs once before the test starts.

Used for:
- Initializing test data
- Checking system availability
- Seeding databases
- Preparing environment state

---

### 2. Default (Execution) Phase
Runs repeatedly for each Virtual User (VU).

Used for:
- Actual load testing
- Sending API requests
- Validating responses
- Simulating user behavior

---

### 3. Teardown Phase
Runs once after the test completes.

Used for:
- Cleanup operations
- Deleting test data
- Closing connections
- Sending notifications

---

## Test Configuration (Load Stages)

The test uses **stages**:

```javascript id="stages_config"
stages: [
  { duration: "5s", target: 5 },
  { duration: "10s", target: 5 },
  { duration: "5s", target: 0 },
]
```

### Behavior:

- Ramp-up to 5 VUs in 5 seconds
- Hold 5 VUs for 10 seconds
- Ramp-down to 0 VUs in 5 seconds

Total execution time: **20 seconds**

## Full Script

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

const BASE_URL = __ENV.BASE_URL || "http://localhost:3333";

/**
 * OPTIONS - Load stages configuration
 */
export const options = {
  stages: [
    { duration: "5s", target: 5 },
    { duration: "10s", target: 5 },
    { duration: "5s", target: 0 },
  ],
};

/**
 * SETUP PHASE
 * Runs once before test execution
 */
export function setup() {
  let res = http.get(BASE_URL);

  if (res.status !== 200) {
    throw new Error(
      `Got unexpected status code ${res.status} during setup. Exiting.`
    );
  }

  return { baseUrl: BASE_URL };
}

/**
 * DEFAULT (EXECUTION PHASE)
 * Runs for each Virtual User
 */
export default function () {
  let restrictions = {
    maxCaloriesPerSlice: 500,
    mustBeVegetarian: false,
    excludedIngredients: ["pepperoni"],
    excludedTools: ["knife"],
    maxNumberOfToppings: 6,
    minNumberOfToppings: 2,
  };

  let res = http.post(
    `${BASE_URL}/api/pizza`,
    JSON.stringify(restrictions),
    {
      headers: {
        "Content-Type": "application/json",
        Authorization: "token abcdef0123456789",
      },
    }
  );

  check(res, {
    "status is 200": (r) => r.status === 200,
  });

  console.log(
    `${res.json().pizza.name} (${res.json().pizza.ingredients.length} ingredients)`
  );

  sleep(1);
}

/**
 * TEARDOWN PHASE
 * Runs once after test execution
 */
export function teardown(data) {
  console.log("That's all folks!");
}
```

---

## Execution Flow

### Step 1: Setup

- Sends a GET request to base URL
- Validates system availability
- Stops test if system is not healthy

---

### Step 2: Load Test Execution

- 5 Virtual Users simulate traffic
- Each VU sends POST request to `/api/pizza`
- Response is validated
- Pizza details are logged
- `sleep(1)` simulates user think time

---

### Step 3: Teardown

- Executes once after test ends
- Used for cleanup or notifications

---

## Key Concepts

### 1. Setup Phase Benefits

- Prevents running tests on unhealthy systems
- Useful for pre-test validation

---

### 2. Execution Phase

- Core testing logic
- Runs for every VU iteration
- Simulates real user behavior

---

### 3. Teardown Phase

- Ensures cleanup after test execution
- Prevents resource leaks
- Can trigger external notifications
