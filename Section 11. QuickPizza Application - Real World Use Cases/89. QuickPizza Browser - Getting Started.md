In this session, we explore the fundamental concept of browser automation using k6’s **experimental browser module**. This feature allows us to automate real browser interactions, making it useful for end-to-end performance testing of web applications.

## Full Script

```javascript
import { browser } from "k6/browser";
import { check } from 'https://jslib.k6.io/k6-utils/1.5.0/index.js';

const BASE_URL = __ENV.BASE_URL || "http://localhost:3333";

export const options = {
  scenarios: {
    ui: {
      executor: "shared-iterations",
      options: {
        browser: {
          type: "chromium",
        },
      },
    },
  },
};

export default async function () {
  let checkData;
  const page = await browser.newPage();

  try {
    await page.goto(BASE_URL);

    checkData = await page.locator("h1").textContent();

    check(checkData, {
      header: checkData == "Looking to break out of your pizza routine?",
    });
    
    await page.getByRole("button", { name: "Pizza, Please!" }).click();
    await page.waitForTimeout(500);
    await page.screenshot({ path: "screenshot.png" });

    checkData = await page.locator("div#recommendations").textContent();

    check(checkData, {
      recommendation: checkData != "",
    });
  } finally {
    await page.close();
  }
}
```

---

### **What this script does**

The script performs the following steps:

- Launches a Chromium browser instance
- Navigates to the base URL
- Validates the page header text
- Clicks a button labeled **"Pizza, Please!"**
- Waits briefly for UI updates
- Captures a screenshot of the page
- Validates that recommendations are displayed

---

### **Step-by-step execution flow**

1. A new browser page is created using:

```javascript
const page = await browser.newPage();
```

2. The script navigates to the application:

```javascript
await page.goto(BASE_URL);
```

3. It validates the page header:

```javascript
await page.locator("h1").textContent();
```

    Then checks if it matches:

    > "Looking to break out of your pizza routine?"

4. It finds and clicks the button:

```javascript
await page.getByRole("button", { name: "Pizza, Please!" }).click();
```

5. It waits for UI updates:

```javascript
await page.waitForTimeout(500);
```

6. It takes a screenshot:

```javascript
await page.screenshot({ path: "screenshot.png" });
```

7. It verifies recommendations section:

```javascript
await page.locator("div#recommendations").textContent();
```


---

### **Checks performed**

The script includes two validations:

- Header text is correct
- Recommendations section is not empty

If these checks pass, the test is considered successful.

---

### **Browser metrics (important concept)**

When running this script, k6 collects **frontend performance metrics**, also known as **Core Web Vitals**, such as:

- **LCP** (Largest Contentful Paint)
- **CLS** (Cumulative Layout Shift)
- **FCP** (First Contentful Paint)
- **FID / INP** (Interaction metrics)
- **TTFB** (Time to First Byte)

These metrics help measure real user experience during browser-based load testing.

---

### **Key idea**

This script demonstrates how k6 can:

- Automate browser actions
- Validate UI behavior
- Capture screenshots for debugging
- Collect real user experience metrics

This makes it useful for combining **functional UI validation + performance testing** in a single test.
