## 🎯 What This Lecture Covers

This lecture demonstrates how to perform **HTTP Basic Authentication** in **K6** using two different approaches:

1. **Embedding username and password directly in the URL**    
2. **Sending credentials through the `Authorization` header using Base64 encoding**

This is useful when testing APIs or endpoints protected with **Basic Auth**.

---

# 🧠 What is Basic Authentication?

**HTTP Basic Authentication** is a simple authentication mechanism where the client sends:

```text
username:password
```

to the server, usually encoded in **Base64** and passed in the request header.

Example header:

```http
Authorization: Basic dXNlcjpwYXNzd2Q=
```

# ✅ Method 1: Basic Authentication by Embedding Credentials in URL

In this approach, the username and password are placed directly inside the request URL.

## Code

```javascript
const credentials = `${username}:${password}`

const url = `https://${credentials}@quickpizza.grafana.com/api/basic-auth/${username}/${password}`
let res = http.get(url)
```

## How it works

The credentials are inserted into the URL like this:

```text
https://username:password@host/path
```

So K6 sends the request with **Basic Authentication automatically**.

# ✅ Validation After Request

After making the request, K6 validates the response using `check()`:

```javascript
check(res, {
  'status is 200': (r) => r.status === 200,
  'is authenticated': (r) => r.json().authenticated === true,
  'is correct user': (r) => r.json().user === username,
});
```

## What is being checked?

### 1. Status Code

```javascript
'status is 200': (r) => r.status === 200
```

Checks if the request was successful.

### 2. Authentication Status

```javascript
'is authenticated': (r) => r.json().authenticated === true
```

Checks if the API confirms the user was authenticated.

### 3. Username Match

```javascript
'is correct user': (r) => r.json().user === username
```

Checks whether the API returned the expected username.

# 🔐 Method 2: Basic Authentication Using Authorization Header

This is the **more common and recommended way** to send Basic Auth credentials.

---

## Step 1: Create `username:password`

```javascript
const credentials = `${username}:${password}`
```

---

## Step 2: Base64 Encode the Credentials

```javascript
const encodedCredentials = encoding.b64encode(credentials)
```

If credentials are:

```text
user:passwd
```

they become something like:

```text
dXNlcjpwYXNzd2Q=
```

---

## Step 3: Create Authorization Header

```javascript
const options = {
  headers: {
    Authorization: `Basic ${encodedCredentials}`,
  },
}
```

This creates a request header like:

```http
Authorization: Basic dXNlcjpwYXNzd2Q=
```

---

## Step 4: Send Request with Header

```javascript
res = http.get(
  `https://quickpizza.grafana.com/api/basic-auth/${username}/${password}`,
  options
)
```

Now K6 sends the request with the authentication header.

---

# ✅ Validate the Second Request

The same checks are used again:

```javascript
check(res, {
  'status is 200': (r) => r.status === 200,
  'is authenticated': (r) => r.json().authenticated === true,
  'is correct user': (r) => r.json().user === username,
});
```

This confirms that the **header-based authentication** also worked correctly.

# 💻 Full Code

```javascript
import encoding from 'k6/encoding'
import http from 'k6/http'
import { check } from 'k6'

const username = 'user'
const password = 'passwd'
export const options = {}

export default function () {
  const credentials = `${username}:${password}`
  
  // Method 1: Username/password directly in URL
  const url = `https://${credentials}@quickpizza.grafana.com/api/basic-auth/${username}/${password}`
  let res = http.get(url)
  
  check(res, {
    'status is 200': (r) => r.status === 200,
    'is authenticated': (r) => r.json().authenticated === true,
    'is correct user': (r) => r.json().user === username,
  });

  // Method 2: Authorization header with Base64 encoded credentials
  const encodedCredentials = encoding.b64encode(credentials)
  const options = {
    headers: {
      Authorization: `Basic ${encodedCredentials}`,
    },
  }

  res = http.get(
    `https://quickpizza.grafana.com/api/basic-auth/${username}/${password}`,
    options
  )

  check(res, {
    'status is 200': (r) => r.status === 200,
    'is authenticated': (r) => r.json().authenticated === true,
    'is correct user': (r) => r.json().user === username,
  });
}
```

# 📌 Two Authentication Approaches Used

## 1. URL-Based Authentication

```javascript
https://username:password@host/path
```

### Pros

- Simple for quick demos    
- Easy to understand

### Cons

- Credentials become visible in the URL
- Not recommended for real-world use

---

## 2. Header-Based Authentication

```javascript
Authorization: Basic <Base64EncodedCredentials>
```

### Pros

- Standard and widely used    
- Cleaner and more secure than URL embedding
- Better for real applications and API testing

### Cons

- Slightly more code than URL method

# ⚠️ Important Notes

## 1. Avoid hardcoding credentials in real projects

Instead of:

```javascript
const username = 'user'
const password = 'passwd'
```

prefer:

```javascript
const username = __ENV.USERNAME
const password = __ENV.PASSWORD
```

This keeps credentials secure and reusable.

---

## 2. Base64 is **not encryption**

Base64 only **encodes** the text. It does **not** protect the password by itself.

That’s why Basic Auth should ideally be used over **HTTPS**.

---

## 3. `check()` is important

Authentication testing is not complete unless you validate:

- request success
- authentication success
- correct user response

# 📘 Quick Interview Notes

## What is Basic Authentication?

Basic Authentication is an HTTP authentication mechanism where the client sends `username:password`, usually Base64 encoded, in the `Authorization` header.

## How can K6 perform Basic Authentication?

K6 can perform Basic Authentication in two ways:

1. by embedding credentials in the request URL
2. by manually creating the `Authorization: Basic <encoded_credentials>` header

## Why is header-based authentication preferred?

Because it is cleaner, more standard, and avoids exposing credentials directly in the URL.
