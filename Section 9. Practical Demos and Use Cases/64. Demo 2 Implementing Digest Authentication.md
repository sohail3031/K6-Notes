**Digest Authentication** is a more secure alternative to **Basic Authentication**.  
In **Basic Auth**, the username and password are sent in **Base64 format**, which is easily decodable.  
In **Digest Auth**, the credentials are **hashed** before being sent, so the actual password is not transmitted in plain text.

# 🔍 Basic Auth vs Digest Auth

| Authentication Type       | How Credentials Are Sent                  | Security Level |
| ------------------------- | ----------------------------------------- | -------------- |
| **Basic Authentication**  | Username + password encoded in Base64     | ❌ Less secure  |
| **Digest Authentication** | Username + password converted into a hash | ✅ More secure  |

👉 So if authentication must be more secure than plain Base64 credentials, **Digest Authentication** is preferred.

# ⚙️ K6 Script for Digest Authentication

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

export const options = {
	vus: 5,
	duration: "1m"
};

const username = "user";
const password = "passwd";

export default function() {
	let res = http.get(
		`http://${username}:${password}@httpbin.org/digest-auth/auth/${username}/${password}`,
		{ auth: "digest" }
	);
	
	check(res, {
		"status is 200": (r) => r.status === 200,
		"is authenticated": (r) => r.json().authenticated === true,
		"is correct user": (r) => r.json().user === username
	});
	
	sleep(1);
}
```

# 🧠 Key Point in Digest Authentication

The main change compared to Basic Auth is this part:

```javascript
{ auth: "digest" }
```

This tells K6 to use **Digest Authentication** instead of normal/basic authentication.

# 🔄 Why Digest Authentication Shows 401 and 200 Responses

When digest auth runs, it usually involves **two-step communication**:

## Step 1: Initial Request

The client sends a request to the server.

## Step 2: Server Responds with 401 Unauthorized

The server replies with **401** and sends digest challenge details such as:

- nonce    
- realm
- other digest parameters

## Step 3: Client Generates Hash

The client uses:

- username
- password
- nonce
- request details

to create a **hash**.

## Step 4: Authenticated Request Sent Again

The client sends another request with the digest hash in the header.

## Step 5: Server Validates and Returns 200

If everything matches, server responds with **200 OK**.

---

# ⚠️ Important Note About 401 Responses in Digest Auth

If you run this test and see both **401** and **200** responses, that is expected.

### Why?

Because:

- **401** = initial challenge from the server    
- **200** = actual successful authenticated request

So in Digest Authentication, the initial **401 is not a failure**.  
It is part of the normal authentication flow.

# ✅ Why Digest Authentication Is Better Than Basic Authentication

## Basic Authentication

- easy to implement    
- sends credentials in Base64
- not secure unless HTTPS is used

## Digest Authentication

- does **not** send password directly
- uses **hashed credentials**
- safer than basic auth for challenge-response authentication
