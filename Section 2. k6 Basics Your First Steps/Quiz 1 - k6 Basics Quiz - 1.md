### Question 1

**What is the primary purpose of performance testing?**

- To find bugs in the code    
- **To ensure software can handle expected workload efficiently** ✅
- To improve the user interface
- To reduce the cost of development

**Correct Answer:** **To ensure software can handle expected workload efficiently**

#### Why this is correct

Performance testing is mainly used to verify whether an application can handle the **expected number of users, requests, and system load** without slowing down, failing, or becoming unstable. It focuses on **speed, scalability, stability, and responsiveness under load**.

#### Why the other options are wrong

- **To find bugs in the code**  
    This is more closely related to **functional testing** or **debugging**. Performance testing may reveal performance-related defects, but its primary goal is not general bug finding.    
- **To improve the user interface**  
    UI improvement is related to **UX/UI design**, not performance testing. Performance testing may improve response time, but it does not directly focus on interface design.
- **To reduce the cost of development**  
    Performance testing can help avoid expensive production issues, but **cost reduction is not its primary purpose**.

### Question 2

**What is a key benefit of identifying and resolving performance bottlenecks before release?**

- Reducing the size of the application    
- **Maintaining seamless user experience** ✅
- Enhancing graphical elements
- Decreasing server costs

**Correct Answer:** **Maintaining seamless user experience**

#### Why this is correct

If performance bottlenecks are found and fixed before release, the application is more likely to remain **fast, stable, and responsive** when real users start using it. That directly improves **user experience** and reduces frustration caused by slow loading, crashes, or timeouts.

#### Why the other options are wrong

- **Reducing the size of the application**  
    Performance testing does not primarily focus on reducing application size. That is more related to optimization of assets, packaging, or architecture decisions.
- **Enhancing graphical elements**  
    Graphics and visual design are unrelated to the main goal of performance testing.
- **Decreasing server costs**  
    Performance testing can indirectly help optimize infrastructure usage, but the **main benefit** of fixing bottlenecks before release is ensuring a better experience for users.

### Question 5

**Performance testing is not just about seeing how fast an application runs. What else does it measure?**

- The number of lines of code    
- **Scalability, reliability, and resource usage** ✅
- The aesthetics of the user interface
- The cost of development

**Correct Answer:** **Scalability, reliability, and resource usage**

#### Why this is correct

Performance testing evaluates how well an application behaves under load by measuring:

- **Scalability** → Can it handle increasing traffic?
- **Reliability/Stability** → Does it remain functional under stress?
- **Resource usage** → How much CPU, memory, bandwidth, etc. does it consume?

#### Why the other options are wrong

- **The number of lines of code**  
    Performance testing does not measure code size. That is a codebase metric, not a runtime performance metric.
- **The aesthetics of the user interface**  
    UI aesthetics are part of design and usability, not performance testing.
- **The cost of development**  
    Development cost is a project/business metric, not a performance metric measured by K6.
