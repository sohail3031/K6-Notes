In this lecture, we will go through another sample K6 script that uses **fixed iterations** along with **Virtual Users (VUs)**.

This configuration is useful when you want the script to run a **specific number of times**, regardless of how long it takes.

---

## Objective of This Example

In this script:

- **10 Virtual Users** will run concurrently
- the script will execute a total of **100 iterations**
- once the iteration count reaches 100, the test will stop automatically
- each iteration will send an HTTP request, validate the response, and then pause for 1 second

---

# K6 Script for Fixed Iterations

```javascript
import http from "k6/http";
import { sleep, check } from "k6";

export const options = {
  vus: 10,
  iterations: 100
};

export default function () {
  let res = http.get("https://test.k6.io");

  check(res, {
    "status is 200": (r) => r.status === 200
  });

  sleep(1);
}
```

---

# Code Breakdown

## 1. Importing Required Modules

```javascript
import http from "k6/http";
import { sleep, check } from "k6";
```

These imports are the same as in the previous example:

- `http` → used to send HTTP requests
- `check` → used to validate the response
- `sleep` → used to simulate user think time

---

## 2. Defining Test Options

```javascript
export const options = {
  vus: 10,
  iterations: 100
};
```

This `options` object defines how the test will execute.

### `vus: 10`

- Specifies the number of **Virtual Users**
- 10 VUs will run concurrently

### `iterations: 100`

- Specifies the **total number of script iterations**
- The script will execute **100 times in total**
- Once the 100 iterations are completed, the test stops automatically

> Unlike a duration-based test, this configuration stops based on **count**, not **time**.

---

## 3. Main Test Logic

```javascript
export default function () {
  let res = http.get("https://test.k6.io");

  check(res, {
    "status is 200": (r) => r.status === 200
  });

  sleep(1);
}
```

The `default()` function contains the actual test logic.

For each iteration, the script:

1. sends a `GET` request to `https://test.k6.io`
2. checks whether the response status is `200`
3. waits for 1 second before continuing

---

## 4. HTTP Request

```javascript
let res = http.get("https://test.k6.io");
```

This sends an HTTP `GET` request to the test URL.

The response is stored in the variable `res`, which can later be used for validation and further checks.

---

## 5. Response Validation with `check()`

```javascript
check(res, {
  "status is 200": (r) => r.status === 200
});
```

This validates that the HTTP response status code is `200`.

If the condition is true, the check passes. Otherwise, it fails.

---

## 6. Simulating Think Time

```javascript
sleep(1);
```

This pauses the Virtual User for **1 second**, simulating real user delay between actions.

# Running the Script

To run the script, open the terminal in the same folder as the file and execute:

```bash
k6 run script.js
```

If your file is named `vus-iterations.js`, then run:

```bash
k6 run vus-iterations.js
```

---

# What Happens During Execution?

When this script runs:

- K6 starts **10 Virtual Users**
- those VUs execute the `default()` function concurrently
- the script continues until the **total iteration count reaches 100**
- after 100 iterations, the test stops automatically

This is different from a duration-based test, where the test runs for a fixed amount of time.

---

# Key Difference: `iterations` vs `duration`

## Using `duration`

- The test runs for a fixed time
- total iterations depend on how fast the script executes

## Using `iterations`

- The test runs for a fixed number of iterations
- total execution time depends on how long those iterations take

# Example Summary

This script demonstrates:

- **10 Virtual Users**
- **100 total iterations**
- each iteration sends a request to `https://test.k6.io`
- validates the response using `check()`
- pauses for 1 second using `sleep()`

# Final Note

The `iterations` option is useful when you want precise control over **how many times** the script runs, rather than **how long** it runs.
