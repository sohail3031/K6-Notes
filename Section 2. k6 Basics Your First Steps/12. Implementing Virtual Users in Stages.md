In this lecture, we will go through a sample K6 script that uses **stages** to control the number of Virtual Users over time.

Using stages allows us to simulate more realistic traffic patterns such as:

- gradually increasing the load
- keeping the load stable for some time
- gradually decreasing the load

This is very useful when we want to test how an application behaves during **ramp-up**, **steady load**, and **ramp-down** phases.

---

# Objective of This Example

In this script, we will configure the test in **three stages**:

1. **Ramp up** from 0 to 20 Virtual Users over 30 seconds  
2. **Maintain** 20 Virtual Users for 1 minute  
3. **Ramp down** from 20 to 0 Virtual Users over 30 seconds  

This helps simulate a realistic load pattern rather than instantly starting all users at once.

---

# K6 Script Using Stages

```javascript
import http from "k6/http";
import { sleep, check } from "k6";

export const options = {
  stages: [
    { duration: "30s", target: 20 }, // ramp up to 20 VUs over 30 seconds
    { duration: "1m", target: 20 },  // stay at 20 VUs for 1 minute
    { duration: "30s", target: 0 }   // ramp down to 0 VUs over 30 seconds
  ]
};

export default function () {
  let res = http.get("https://test.k6.io");

  check(res, {
    "status is 200": (r) => r.status === 200
  });

  sleep(1);
}
```

import http from "k6/http";

These imports are used for:

- `http` → sending HTTP requests

---

## 2. Defining Test Options with `stages`

```javascript
export const options = {
  stages: [
    { duration: "30s", target: 20 },
    { duration: "1m", target: 20 },
    { duration: "30s", target: 0 }
  ]
};
```

The `stages` option is an array of objects.

Each object defines a phase of the test with:

- `duration` → how long that stage lasts
- `target` → how many Virtual Users should be active by the end of that stage

---

# Stage-by-Stage Explanation

## Stage 1: Ramp Up

```javascript
{ duration: "30s", target: 20 }
```

This stage ramps the number of Virtual Users from the current count to **20** over **30 seconds**.

Since the test starts from **0 VUs**, K6 will gradually increase the user count from **0 to 20** during the first 30 seconds.

### What this simulates

A gradual increase in traffic, similar to users slowly arriving at the application.

---

## Stage 2: Maintain Constant Load

```javascript
{ duration: "1m", target: 20 }
```

This stage keeps the number of Virtual Users at **20** for **1 minute**.

Since the previous stage already ramped up to 20 users, K6 will now maintain that same load for the full duration of this stage.

### What this simulates

A stable load period where a constant number of users are interacting with the application.

---

## Stage 3: Ramp Down

```javascript
{ duration: "30s", target: 0 }
```

This stage gradually reduces the number of Virtual Users from **20 to 0** over **30 seconds**.

### What this simulates

Users slowly leaving the application, reducing the traffic load until the test ends.

---

# Main Test Logic

```javascript
export default function () {
  let res = http.get("https://test.k6.io");

  check(res, {
    "status is 200": (r) => r.status === 200
  });

  sleep(1);
}
```

The `default()` function is the test logic executed by each Virtual User.

For every iteration, each Virtual User will:

1. send a `GET` request to `https://test.k6.io`
2. verify that the response status is `200`
3. wait for 1 second using `sleep(1)`

---

# Load Pattern of This Test

The script creates the following load pattern:

## Phase 1: Ramp-Up

- Time: `0s → 30s`
- VUs: `0 → 20`

## Phase 2: Constant Load

- Time: `30s → 1m 30s`
- VUs: `20`

## Phase 3: Ramp-Down

- Time: `1m 30s → 2m`
- VUs: `20 → 0`

So the total test duration is:

```text
30s + 1m + 30s = 2 minutes
```

# What Happens During Execution?

When the test starts:

- K6 begins with **0 Virtual Users**
- over the first **30 seconds**, the number of users gradually increases to **20**
- for the next **1 minute**, K6 keeps **20 users active**
- during the last **30 seconds**, K6 gradually reduces the number of users back to **0**
- once all stages are complete, the test stops

---

# Why Use Stages?

Using stages is useful because it allows us to simulate **realistic traffic patterns**.

Instead of suddenly launching all users at once, we can model:

- traffic growth over time
- stable peak usage
- traffic decline after peak usage

This helps us understand how the system behaves under changing load conditions.
