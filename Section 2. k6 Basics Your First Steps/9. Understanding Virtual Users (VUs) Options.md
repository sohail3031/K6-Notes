Welcome to today’s lecture on **Virtual Users (VUs)**, a core concept in K6.

Virtual Users are essential for simulating real-world user behavior during load testing. By understanding and using VUs effectively, we can ensure that an application performs well under different traffic conditions.

---

## Why Virtual Users Matter

In performance testing, it is important to simulate multiple users interacting with the application at the same time.

This helps us:

- Identify performance bottlenecks
- Measure system behavior under load
- Validate whether the application can handle expected traffic

In K6, **Virtual Users (VUs)** allow us to do exactly that by running multiple instances of a test script concurrently.

Each VU behaves like an independent user interacting with the application.

---

## What Are Virtual Users (VUs)?

A **Virtual User (VU)** in K6 is a simulated user that executes your test script.

- Each VU runs the `default()` function
- Multiple VUs run concurrently
- They help generate realistic load on the system
- Each VU behaves like an independent session

---

# VU Options in K6

K6 provides several options to control how Virtual Users behave during a test.

The most commonly used VU-related options are:

- `vus`
- `duration`
- `stages`
- `iterations`
- `vusMax`
- `startVUs`

These options can be configured in multiple ways:

- Directly inside the JavaScript script
- Through command-line arguments
- Using environment variables

We will explore precedence and different ways of setting these options in upcoming lectures.

---

## 1. `vus`

The `vus` option sets the number of Virtual Users to run concurrently.

It determines how many users will execute the test script at the same time.

### Example
```javascript
export const options = {
  vus: 10
};
```

This means **10 Virtual Users** will run concurrently.

---

## 2. `duration`

The `duration` option specifies how long the test should run.

### Example

```javascript
export const options = {
  vus: 10,
  duration: "1m"
};
```

This means:

- 10 Virtual Users will run
- The test will execute for 1 minute

---

## Fixed Number of VUs for a Fixed Duration

This is one of the simplest and most commonly used K6 configurations.

```javascript
export const options = {
  vus: 10,
  duration: "1m"
};
```

### Explanation

- `vus: 10` → Run 10 Virtual Users concurrently
- `duration: "1m"` → Run the test for 1 minute

---

## 3. `stages`

The `stages` option allows you to define different phases of load with varying VU counts and durations.

It is useful for simulating:

- Ramp-up
- Sustained load
- Ramp-down

Each stage contains:

- `duration` → how long the stage lasts
- `target` → target number of VUs for that stage

---

## Example: Ramp-Up and Ramp-Down Using Stages

```javascript
export const options = {
  stages: [
    { duration: "30s", target: 20 }, // ramp up to 20 VUs
    { duration: "1m", target: 20 },  // stay at 20 VUs
    { duration: "30s", target: 0 }   // ramp down to 0 VUs
  ]
};
```

### How this works

1. Ramp up from 0 to 20 VUs over 30 seconds
2. Stay at 20 VUs for 1 minute
3. Ramp down from 20 to 0 VUs over 30 seconds

This creates a load pattern like:

- **Ramp-up**
- **Steady load**
- **Ramp-down**

---

## 4. `iterations`

The `iterations` option sets the total number of script iterations to execute.

This is useful when you want to perform a fixed number of operations, regardless of time.

### Example

```javascript
export const options = {
  iterations: 100,
  vus: 10
};
```

This means:

- The script will run **100 total iterations**
- These iterations will be distributed across **10 Virtual Users**

---

## Fixed Number of Iterations

```javascript
export const options = {
  iterations: 100,
  vus: 10
};
```

### Explanation

- `iterations: 100` → Execute the script 100 times in total
- `vus: 10` → Use 10 Virtual Users to perform those iterations

---

## 5. `vusMax`

The `vusMax` option specifies the **maximum number of Virtual Users** that can be used during a test, especially when working with more advanced execution models or ramping scenarios.

It acts as an upper limit for VU allocation.

---

## 6. `startVUs`

The `startVUs` option defines the **initial number of Virtual Users** at the beginning of a staged or ramping test.

This is useful when you do not want the test to start from zero users.

---

# Summary of VU Options

|Option|Purpose|
|---|---|
|`vus`|Number of concurrent Virtual Users|
|`duration`|Total test duration|
|`stages`|Defines ramp-up, steady load, and ramp-down phases|
|`iterations`|Total number of script iterations|
|`vusMax`|Maximum allowed VUs during a test|
|`startVUs`|Initial number of VUs at the beginning of a test|
