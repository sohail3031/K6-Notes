In this lecture, we will understand how to read and analyze the **output summary generated by K6** after running a performance test.

When a K6 script is executed, it prints a summary to the console that contains useful information about:

- the execution environment
- the test scenario
- HTTP request statistics
- checks and assertions
- Virtual User activity
- iteration details
- network usage

Understanding this output is essential for diagnosing performance issues and evaluating how the application behaved during the test.

---

# K6 Script Used in This Example

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

// optional setup function
export function setup() {
  // initialize data if needed
  console.log("Setup: Initializing data...");
}

// main test logic
export default function () {
  // make a GET request to the test API
  let res = http.get("https://test.k6.io");

  // check if the response status is 200
  check(res, {
    "status was 200": (r) => r.status === 200
  });

  // sleep for 1 second to simulate real user behavior
  sleep(1);
}

// optional teardown function
export function teardown() {
  // cleanup if needed
  console.log("Teardown: Cleaning up...");
}
```

# Understanding the K6 Output Summary

## 1. `execution`

```text
execution: local
```

This tells us **where the script was executed**.

- `local` means the script was run on the local machine
- if a cloud or remote output system were used, it would be reflected differently

---

## 2. `script`

```text
script: script.js
```

This shows the name of the JavaScript file that was executed.

In this case, the file name is:

```text
script.js
```

---

## 3. `output`

```text
output: -
```

This indicates where the results are being sent.

- `-` means the results are being printed directly to the **console**    
- if an output backend such as JSON, CSV, InfluxDB, or Grafana Cloud were configured, it would be shown here instead

---

# Scenario Information

## 4. `scenarios`

```text
scenarios: (100.00%) 1 scenario, 1 max VUs, 10m30s max duration (incl. graceful stop):
          * default: 1 iterations for each of 1 VUs (maxDuration: 10m0s, gracefulStop: 30s)
```

This section describes the **test scenario configuration**.

### Breakdown

- **1 scenario** → only one scenario is defined    
- **1 max VUs** → maximum number of Virtual Users is 1
- **10m30s max duration** → maximum total duration including graceful stop time

---

## 5. `default`

```text
* default: 1 iterations for each of 1 VUs (maxDuration: 10m0s, gracefulStop: 30s)
```

This line describes the actual default scenario that was executed.

It means:

- the scenario name is `default`    
- **1 VU** was used
- **1 iteration** was executed
- maximum duration allowed was **10 minutes**
- graceful stop time was **30 seconds**

# HTTP Metrics

## 10. `http_req_duration`

```text
http_req_duration..............: avg=196.26ms min=87.06ms med=196.26ms max=305.45ms p(90)=283.61ms p(95)=294.53ms
```

This is one of the most important K6 metrics.

It shows the **total time taken for an HTTP request**, including:

- connection time    
- sending the request
- waiting for the response
- receiving the response

### Meaning of each value

- **avg** → average request duration
- **min** → minimum request duration
- **med** → median request duration
- **max** → maximum request duration
- **p(90)** → 90th percentile
- **p(95)** → 95th percentile

### In this example

- average response time = **196.26 ms**
- fastest request = **87.06 ms**
- slowest request = **305.45 ms**

---

## 11. `{ expected_response:true }`

```text
{ expected_response:true }...: avg=196.26ms ...
```

This is the same request duration metric, but filtered only for requests that K6 considers **expected successful responses**.

In this case, both requests were expected and successful, so the values are the same.

# Summary of Common K6 Output Fields

| Field                | Meaning                            |
| -------------------- | ---------------------------------- |
| `execution`          | Where the test ran                 |
| `script`             | Name of the script file            |
| `output`             | Where the results are sent         |
| `scenarios`          | Scenario configuration summary     |
| `checks_total`       | Total checks executed              |
| `checks_succeeded`   | Number/percentage of passed checks |
| `checks_failed`      | Number/percentage of failed checks |
| `http_req_duration`  | Total HTTP request duration        |
| `http_req_failed`    | Failed HTTP requests               |
| `http_reqs`          | Total number of HTTP requests      |
| `iteration_duration` | Total time per iteration           |
| `iterations`         | Number of completed iterations     |
| `vus`                | Active Virtual Users               |
| `vus_max`            | Maximum allocated Virtual Users    |
| `data_received`      | Total data received                |
| `data_sent`          | Total data sent                    |

---

# Final Note

The K6 output summary is extremely important because it gives a quick overview of:

- request performance    
- success/failure rates
- Virtual User activity
- total execution behavior

As you continue learning K6, you will encounter more metrics such as:

- blocking time
- connecting time
- TLS handshake time
- waiting time
- custom metrics
- thresholds and pass/fail criteria

Understanding the default output summary is the first step toward analyzing performance test results effectively.
