### What is the `constant-vus` executor?

The **`constant-vus`** executor in **k6** keeps a **fixed number of Virtual Users (VUs)** running for a **specified duration**.

This means:

- k6 starts the configured number of VUs
- those VUs continuously execute the `default` function
- they keep running for the full duration of the test
- k6 does **not** stop after a fixed number of iterations; instead, it runs **as many iterations as possible** during the time limit

It is one of the most commonly used executors because it is simple and useful for applying a **steady load** on the system.

---

# Why use `constant-vus`?

This executor is useful when you want to simulate **continuous traffic from a fixed number of users**.

### Common use cases

- **Baseline performance testing**  
    Measure response time, throughput, and error rate under a stable load.    
- **Stress / load testing with fixed concurrency**  
    Example: “Can the application handle 10 users continuously for 30 seconds?”
- **Stability testing**  
    Keep a constant load for a longer duration to check for:
    - memory leaks
    - slowdowns over time
    - resource exhaustion
    - connection issues

---

# Example Script

```javascript
import http from "k6/http";
import { sleep } from "k6";

export let options = {
	discardResponseBodies: true,
	scenarios: {
		contacts: {
			executor: "constant-vus", // maintain constant VUs throughout the test
			vus: 10, // number of VUs
			duration: "30s" // duration to execute the script
		}
	}
};

export default function() {
	http.get("https://test.k6.io/contacts.php");
	
	sleep(1);
}
```

# Understanding the executor settings

## `executor: "constant-vus"`

This tells k6 to use the **constant virtual users executor**.

### Behavior

- Start the configured VUs
- Keep them running for the full duration
- Each VU repeatedly executes the `default` function
- Stop after the configured duration ends

---

## `vus: 10`

```javascript
vus: 10
```

This means **10 virtual users** will run concurrently.

Think of it as:

- 10 users using the application at the same time
- each user repeatedly executes the script

---

## `duration: "30s"`

```javascript
duration: "30s"
```

This means the test will run for **30 seconds**.

During these 30 seconds:

- all 10 VUs stay active
- each VU keeps executing iterations again and again
- the total number of iterations depends on:
    - response time
    - sleep time
    - server speed
    - network latency

---

# Default function

```javascript
export default function() {
	http.get("https://test.k6.io/contacts.php");
	
	sleep(1);
}
```

This is the function each VU runs repeatedly.

### In every iteration, a VU does:

1. Send a GET request to:

```javascript
https://test.k6.io/contacts.php
```

2. Wait for 1 second    
3. Start the next iteration
4. Continue doing this until the scenario duration ends

---

# How the execution works step by step

## Test start

k6 initializes **10 VUs**.

## During execution

Each VU repeatedly does:

```javascript
http.get(...)
sleep(1)
```

So all 10 VUs keep looping through the same logic.

## Test end

After **30 seconds**, k6 stops the scenario.

---

# Important behavior of `constant-vus`

## It does **not** guarantee a fixed number of iterations

Unlike:

- `shared-iterations`    
- `per-vu-iterations`

the `constant-vus` executor is **time-based**, not iteration-based.

That means:

- k6 does **not** say “run exactly 100 iterations”
- instead it says:  
    **“keep 10 users active for 30 seconds and let them execute as much work as possible”**

So the total iterations may vary from one run to another depending on:

- API response speed
- system performance
- network conditions
- `sleep()` duration

---

# Approximate execution example

Suppose each iteration takes about:

- request time = **200 ms**    
- sleep time = **1000 ms**

Total ≈ **1.2 seconds per iteration per VU**

For one VU in 30 seconds:

- about **25 iterations**

For 10 VUs:

- about **250 total iterations**

This is just an estimate — the real number depends on actual execution time.

---

# What stays constant here?

With `constant-vus`, the **number of active users stays constant**, not the iteration rate.

So in this script:

- **VUs remain constant = 10**    
- **duration remains constant = 30s**
- **iterations are variable**

---

# Output metrics you should focus on

When running this script, pay attention to:

## 1) `vus`

Shows the number of active virtual users.

For this script, it should remain around **10** during the test.

---

## 2) `http_reqs`

Total number of HTTP requests sent.

Since each iteration sends **one GET request**, this roughly matches the total iterations.

---

## 3) `iteration_duration`

Time taken for one full iteration, including:

- request time    
- sleep time
- any extra logic inside `default`

---

## 4) `http_req_duration`

Time taken only for the HTTP request itself.

This includes:

- sending request    
- waiting for response
- receiving response

It does **not** include `sleep()`.

---

## 5) `iterations`

Total number of completed iterations during the test.

This depends on:

- test duration    
- request speed
- sleep time
- number of VUs

---

## 6) `http_req_failed`

Shows failed requests, if any.

Useful for checking system reliability under constant load.

Use this executor when you want:

## 1. Steady concurrent load

Example:

- 50 users constantly browsing your site for 5 minutes    

## 2. Baseline performance measurement

Example:

- measure average response time with 20 users active

## 3. Stability / soak testing

Example:

Example:

- another with 100 VUs

- response time

# Difference from earlier executors

## `shared-iterations`

- Fixed total iterations across all VUs
- Test ends when those iterations finish

Example:

```javascript
vus: 10
iterations: 100
```

This means 100 total iterations shared across 10 VUs.

---

## `per-vu-iterations`

- Fixed number of iterations for each VU

Example:

```javascript
vus: 10
iterations: 5
```

This means:

- each VU does 5 iterations
- total = 50 iterations

---

## `constant-vus`

- Fixed number of VUs
- Fixed duration
- iterations are not fixed

Example:

```javascript
vus: 10
duration: "30s"
```

---

# Quick comparison table

| Executor            |                              Controls | Best for                                   |
| ------------------- | ------------------------------------: | ------------------------------------------ |
| `shared-iterations` |                Fixed total iterations | Complete a fixed amount of work            |
| `per-vu-iterations` |               Fixed iterations per VU | Ensure equal work per user                 |
| `constant-vus`      | Fixed concurrent users for a duration | Steady load / baseline / stability testing |

---

# Key takeaways

## `constant-vus` means:

- maintain a **constant number of virtual users**
- run for a **fixed duration**
- each VU repeatedly executes the `default` function
- total iterations are **not fixed**
- useful for **steady load testing**

# Final summary

In this script:

- **10 VUs** are created    
- they remain active for **30 seconds**
- each VU repeatedly:
    - sends a GET request to the contacts page
    - sleeps for 1 second
- k6 keeps the number of users constant throughout the test
- the total number of iterations depends on how fast each iteration completes

So the main purpose of this executor is to answer questions like:

- **How does my application behave when 10 users are continuously active?**
- **Can the system stay stable under a constant load for a period of time?**
- **What response time and throughput do I get under steady traffic?**
