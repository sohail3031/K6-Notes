## **What is the Per-VU Iterations Executor?**

The **`per-vu-iterations` executor** ensures that **each virtual user (VU) executes a fixed number of iterations independently**.

This is useful when you want:

- Every VU to perform the **same amount of work**    
- Equal workload distribution across users
- More controlled simulation of user journeys

---

## **How It Works**

With `per-vu-iterations`:

- You define the **number of VUs**
- You define the **number of iterations per VU**
- Each VU executes its assigned iterations independently
- Total iterations = **VUs × iterations per VU**

### **Example**

If:

- `vus: 10`
- `iterations: 5`

Then:

- Each VU runs **5 iterations**
- Total test iterations = **10 × 5 = 50**

---

## **When to Use Per-VU Iterations**

Use this executor when:

- You want **every user to perform the same number of actions**
- You want to simulate **equal user journeys**
- You need **predictable workload per user**

### **Typical Use Cases**

- **User journey simulation**  
    Example: every user logs in, browses, and logs out exactly 3 times
- **Form submission testing**  
    Example: each VU submits a registration form 5 times
- **Controlled workload distribution**  
    Example: ensuring each virtual user performs the same number of API calls

---

## **Key Characteristics**

- Fixed number of iterations **per VU**
- Equal workload distribution among VUs
- Total iterations are predictable
- Test ends when all VUs complete their assigned iterations or when `maxDuration` is reached

---

## **Code Example**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export let options = {
	scenarios: {
		per_vu_iterations_scenario: {
			executor: "per-vu-iterations",
			vus: 10,          // number of virtual users
			iterations: 5,    // iterations per VU
			maxDuration: "1m" // maximum allowed duration
		}
	}
};

export default function () {
	http.get("https://test-api.k6.io/public/crocodiles/");
	sleep(1);
}
```

---

## **Expected Behavior**

With the above configuration:

- K6 starts **10 VUs**
- Each VU executes **5 iterations**
- Total iterations = **50**
- The test completes when all 50 iterations are done

---

## **Important Note**

In `per-vu-iterations`, the `iterations` value is **per virtual user**, **not total**.

So this:

```javascript
vus: 10,
iterations: 5
```

means:

```javascript
Total iterations = 10 × 5 = 50
```

---

## **Per-VU Iterations vs Shared Iterations**

| Feature               | `per-vu-iterations` |   `shared-iterations` |
| --------------------- | ------------------: | --------------------: |
| Iterations assignment |        Fixed per VU |  Shared among all VUs |
| Workload distribution |                Even |      Uneven / dynamic |
| Total iterations      |  `vus × iterations` | Explicit total number |
| Best for              | Equal user behavior |  Fixed total workload |

---

## **Common Mistake in the Original Notes**

Your code comment says:

```javascript
iterations: 5, // number of iterations
```

That comment is slightly misleading. It should be:

```javascript
iterations: 5, // number of iterations per VU
```

because in this executor, iterations are **per VU**, not total iterations.

---

## **Summary**

The **`per-vu-iterations` executor** is ideal when you want **every virtual user to perform the same number of iterations**. It is especially useful for **consistent user journey testing, equal workload distribution, and predictable execution patterns**.
