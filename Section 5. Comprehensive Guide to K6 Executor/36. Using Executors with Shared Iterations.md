## **What is Shared Iterations Executor?**

The **shared-iterations executor** distributes a **fixed number of iterations across multiple virtual users (VUs)**.

Instead of assigning iterations per user, K6:

- Maintains a pool of VUs    
- Assigns iterations dynamically
- Reuses VUs until all iterations are completed

---

## **Key Idea**

👉 Focus is on **total number of iterations**, not on execution time per VU.

- If a VU finishes early, it takes another iteration
- Work is distributed dynamically
- Iterations are **not evenly split per VU**

---

## **When to Use Shared Iterations**

Use this executor when:

- You want to execute a **fixed workload**
- You don’t care how long individual VUs take
- You want fast execution of a known number of requests

### **Example Use Cases**

- Running 1000 API calls for quick validation
- Smoke testing APIs
- Early-stage performance testing (shift-left testing)

---

## **How It Works**

1. K6 starts the defined number of VUs
2. Total iterations are placed in a shared pool
3. Each VU picks an iteration when it becomes free
4. Execution continues until all iterations are completed

---

## **Important Characteristics**

- Total iterations are fixed (e.g., 100)
- VUs are constant during execution
- Execution time depends on system performance
- Iterations are **not guaranteed to be evenly distributed**
- Test ends when all iterations are completed OR maxDuration is reached

---

## **Code Example**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export let options = {
	scenarios: {
		shared_iterations_scenario: {
			executor: "shared-iterations",
			vus: 10,
			iterations: 100,
			maxDuration: "1m"
		}
	}
};

export default function () {
	http.get("https://test-api.k6.io/public/crocodiles/");
	sleep(1);
}
```

---

## **Output Behavior (Conceptually)**

- 10 VUs start execution
- 100 total iterations are shared
- Some VUs may execute more iterations than others
- Test completes once all 100 iterations are done

---

## **Common Mistakes**

❌ Thinking each VU gets equal iterations  
✔ Actually iterations are dynamically shared

❌ Using it for precise load simulation  
✔ Better for fixed workload testing, not realistic traffic modeling

---

## **Quick Comparison**

| Executor          | Behavior                                |
| ----------------- | --------------------------------------- |
| shared-iterations | Fixed total iterations shared among VUs |
| per-vu-iterations | Fixed iterations per VU                 |

---

## **Summary**

The **shared-iterations executor** is best used when you want to complete a **fixed number of requests as quickly and efficiently as possible**, without worrying about per-user distribution or realistic traffic simulation.
