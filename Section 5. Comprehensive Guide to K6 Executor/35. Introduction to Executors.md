### **What are Executors?**

Executors in K6 define **how virtual users (VUs) are scheduled and how load is generated over time** during a performance test.

They control:

- Number of virtual users    
- Number of iterations
- Duration of the test
- Load pattern (steady, ramp-up, spike, etc.)

Choosing the right executor is essential to **simulate real-world traffic behavior accurately**.

---

## **Why Executors are Important**

Executors help you:

- Model real production traffic patterns
- Simulate realistic user behavior
- Control load intensity and timing
- Design different performance test scenarios (load, stress, spike testing)

---

## **Types of Executors in K6**

### **1. constant-vus**

Maintains a fixed number of virtual users for a specific duration.

- **Use case:** Steady load testing
- **Example:** 10 users continuously accessing a website for 30 seconds

✔ Best for: baseline performance testing

---

### **2. ramping-vus**

Gradually increases or decreases the number of virtual users over time.

- **Use case:** Simulating traffic growth or drop
- **Example:** Slowly increasing users during a product launch

✔ Best for: load progression testing

---

### **3. constant-arrival-rate**

Maintains a fixed number of iterations (requests) per time unit.

- **Use case:** Controlling request throughput
- **Example:** 10 requests per second to test API stability

✔ Best for: stress testing APIs

---

### **4. ramping-arrival-rate**

Gradually increases or decreases request rate over time.

- **Use case:** Simulating traffic spikes
- **Example:** E-commerce flash sale traffic

✔ Best for: realistic traffic variation

---

### **5. per-vu-iterations**

Each virtual user runs a fixed number of iterations.

- **Use case:** Per-user task repetition
- **Example:** Each user registers 5 times

✔ Best for: user-flow testing

---

### **6. shared-iterations**

Fixed number of iterations shared among all virtual users.

- **Use case:** Controlled total workload
- **Example:** 100 total search queries across all users

✔ Best for: workload distribution testing

---

### **7. externally-controlled**

Virtual users are controlled dynamically via external API.

- **Use case:** Real-time load adjustment
- **Example:** Integrating with monitoring tools to increase/decrease load

✔ Best for: adaptive testing environments

---

## **Summary**

Executors are the backbone of load modeling in K6. Each executor represents a different way of simulating user behavior, and selecting the correct one ensures your test closely reflects real-world application usage.
