## Overview

In k6, you can use **`handleSummary()`** not only to save results to a file, but also to **send the final test summary to a remote server**.

This is useful when you want to:

- send performance results to a **dashboard**    
- push results to a **reporting system**
- trigger a **webhook**
- store test summaries in a **centralized service**

---

# Important Concept

`handleSummary(data)` runs **after the test finishes** and receives the **aggregated test summary object**.

Inside this function, you can:

- write summary data to a file    
- print custom output
- **send the summary to an external HTTP endpoint**

---

# Corrected Note About the Code

The explanation says the script is **posting** summary data to a remote server, but the code shown actually uses **`http.get()`**, which is incorrect for sending JSON data in the request body.

If you want to **send summary data to a remote host**, you should use **`http.post()`**, not `http.get()`.

# Corrected Version of the Code

```javascript
import http from "k6/http";
import k6example from "https://raw.githubusercontent.com/grafana/k6/master/examples/thresholds_readme_example.js";

export const options = {
	vus: 5,
	iterations: 10
};

export default k6example;

export function handleSummary(data) {
	const res = http.post(
		"https://httpbin.test.k6.io/anything",
		JSON.stringify(data),
		{
			headers: {
				"Content-Type": "application/json"
			}
		}
	);

	if (res.status !== 200) {
		console.error("Could not send summary, got status " + res.status);
	}
}
```

# Execution Flow

When you run:

```bash
k6 run post-to-remote.js
```

k6 does the following:

1. Runs the main performance test    
2. Collects all metrics during execution
3. Aggregates the results after the test completes
4. Calls `handleSummary(data)`
5. Sends the summary JSON to the remote endpoint
6. Logs an error if the request fails

# Important Notes / Corrections

## 1) Use `http.post()`, not `http.get()`

If you are **sending summary data**, use:

```javascript
http.post(url, JSON.stringify(data), params)
```

not:

```javascript
http.get(url, JSON.stringify(data))
```

because GET requests are not intended for sending a JSON request body in this way.

---

## 2) Add headers when sending JSON

It is better to include:

```javascript
headers: {
  "Content-Type": "application/json"
}
```

so the remote system knows the payload is JSON.

---

## 3) `handleSummary()` is for end-of-test summary data

This function does **not stream live metrics during the test**.  
It only runs **once at the end** and sends the final aggregated summary.

If you want **real-time metrics streaming**, that is a different mechanism such as:

- InfluxDB
- Prometheus remote write
- Grafana Cloud outputs
