In k6, **result output** is how you capture and inspect the performance data generated during a test run. By default, k6 prints a **summary to the terminal**, but it also supports **custom summaries**, **structured file outputs**, and **streaming metrics to external tools** like Grafana, Prometheus, or InfluxDB.

Understanding these output options is important because running a load test is only half the job—the other half is **analyzing the results**. k6 gives you several ways to do that depending on whether you want a quick console summary, a machine-readable report, or live dashboards.

---



## Ways to Output Results in k6

k6 supports **four common result output approaches**:

1. **Command-line summary output**  
    The default output shown in the terminal after the test run finishes.    
2. **Custom summary using `handleSummary()`**  
    Lets you generate reports in formats such as **JSON**, **HTML**, or custom text files.
3. **Streaming metrics to external systems**  
    Send live metrics to platforms such as **Grafana Cloud**, **InfluxDB**, or **Prometheus-compatible backends** for visualization and monitoring.
4. **Store results locally in a file**  
    Save detailed metrics to a local file for later processing or integration with other tools.

---

## 1) Command-Line Output

This is the default behavior of k6. When you run a script, k6 prints an **aggregated summary** in the terminal.

### What it usually includes

The summary typically contains built-in metrics such as:

- **`http_req_duration`** – request duration    
- **`http_req_failed`** – failure rate
- **`iterations`** – number of completed iterations
- **`vus` / `vus_max`** – active and maximum virtual users
- **data sent / received**
- **checks** results, if checks are used

### Aggregated statistics commonly shown

For many metrics, k6 reports summary values such as:

- **avg** – average
- **min** – minimum
- **med** – median
- **max** – maximum
- **p(90), p(95)** – percentiles

### Example

```bash
k6 run script.js
```

This is the quickest way to inspect test results during development or while learning k6.

---

## 2) Custom Summary with `handleSummary()`

If you want more control over the final test report, k6 provides the **`handleSummary()`** function.

### What `handleSummary()` does

- Runs **after the test finishes**    
- Receives the full aggregated summary data
- Lets you decide:
    - **what format** to output
    - **what file(s)** to write
    - **what content** should go into each report

This is useful when you want:

- a **JSON report** for automation
- an **HTML report** for sharing
- a **custom text report**
- different outputs for different consumers

### Important point

`handleSummary()` works with the **aggregated final summary**, not raw per-sample live metrics.

### Example

```javascript
export function handleSummary(data) {
	return {
		"summary.json": JSON.stringify(data, null, 2),
		stdout: "Test completed successfully\n",
	};
}
```

### In this example

- `summary.json` → stores the aggregated results in JSON format
- `stdout` → prints custom text to the terminal

---

## 3) Streaming Metrics to External Systems

Sometimes a terminal summary is not enough—especially for larger performance tests, trend analysis, dashboards, or team monitoring. In such cases, k6 can **stream metrics to external systems**.

### Common use cases

- Live monitoring during a long-running load test    
- Creating dashboards in **Grafana**
- Storing time-series data for historical comparison
- Sharing test results with teams in a centralized monitoring system

### Common external destinations

- **Grafana Cloud**
- **InfluxDB**
- **Prometheus-compatible systems**
- other supported output backends

### How it works

You typically use the `--out` flag when running the script.

### Example

```bash
k6 run --out json=result.json script.js
```

Or stream to a backend supported by your environment, such as InfluxDB or Grafana Cloud.

### Why use streaming output?

Because it gives you **time-series data during the run**, rather than only a final summary at the end.

---

## 4) Storing Results in a Local File

k6 also allows saving results locally in a file, which is useful when:

- you want to archive test runs    
- you need to process results in another system
- you want to generate reports later
- you are integrating k6 into CI/CD pipelines

A local file output is especially useful when you want **structured data** rather than just terminal output.

### Example

```bash
k6 run --out json=results.json script.js
```

This writes metric data into a JSON file that can be parsed later.

---

# Difference Between Summary Output and File/Streaming Output

This distinction is important:

## **Command-line summary / `handleSummary()`**

These focus on the **final aggregated results** after the test completes.

Examples:

- total requests
- average response time
- percentile values
- failure rate

## **`--out` streaming/file outputs**

These are typically used to **record metric samples over time** or send them to another system.

Examples:

- sending time-series metrics to dashboards
- collecting rawer data for visualization
- storing execution metrics continuously during the test

---

# When to Use Each Output Type

## Use **command-line output** when:

- you want a quick test summary    
- you are learning or debugging a script
- you only need high-level results

## Use **`handleSummary()`** when:

- you want a custom final report
- you need JSON/HTML output after the test
- you want to control the final report structure

## Use **streaming output / `--out`** when:

- you want live dashboards
- you are integrating with monitoring tools
- you need long-term storage and trend analysis

## Use **local file output** when:

- you want to save results for later analysis
- you need to feed results into another tool or script
- you want CI/CD artifacts

---

# Key Takeaways

- k6 supports **multiple result output methods**, not just the terminal summary.    
- The **default terminal output** gives a quick aggregated view of test performance.
- **`handleSummary()`** is used to create **custom final reports** such as JSON or HTML.
- The **`--out` option** is used to **stream or store metrics** externally.
- Choosing the right output method depends on whether you want:
    - a quick summary,        
    - a final custom report,
    - a saved file,
    - or live dashboard metrics.

k6 results can be output in the following ways:

1. **Output to the command line**

3. **Stream metrics to external platforms like Grafana Cloud**
4. **Store results locally in a file**
