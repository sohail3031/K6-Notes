After a k6 test run finishes, you may want to **generate a customized summary report** instead of relying only on the default terminal output. For that, k6 provides the **`handleSummary()`** function.

`handleSummary()` is a special function that k6 automatically calls **at the end of the test run**. It receives a **summary data object** containing the **aggregated test metrics**, and it lets you control **how and where the final summary should be written**.

This is useful when you want to:

- save the final report to a **JSON file**
- create a **custom HTML or text report**
- post-process the summary data before exporting it
- send the final summary to multiple destinations

---

# What is `handleSummary()`?

`handleSummary()` is a **built-in k6 lifecycle function** that runs **after test execution completes**.

It receives a single argument:

- **`data`** → an object containing the **aggregated results** of the entire test run    

You can then use that object to:

- inspect the collected metrics
- transform or filter the summary data
- write the output to one or more files
- print a custom message to the console

---

# Basic Example

```javascript
import http from "k6/http";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	return {
		"summary.json": JSON.stringify(data)
	};
}
```

---

# How This Example Works

## 1) Test execution

The `default` function sends a request to:

```javascript
http.get("https://test.k6.io");
```

k6 runs the test as usual and collects metrics during execution.

---

## 2) End of test

After the test finishes, k6 automatically calls:

```javascript
handleSummary(data)
```

The `data` parameter contains the **final aggregated summary** of the test.

---

## 3) Returning output destinations

The function returns an object:

```javascript
return {
	"summary.json": JSON.stringify(data)
};
```

This tells k6:

- create a file named **`summary.json`**    
- write the JSON string version of the summary data into it

So after execution, you will get a file called **`summary.json`** in the current directory.

---

# What is Inside the `data` Object?

The `data` object contains the **aggregated summary of the test results**. It includes built-in metrics such as:

- request duration    
- number of requests
- number of iterations
- failure rates
- VU information
- checks
- custom metrics (if you created any)

For example, the summary may include metrics like:

- **`http_req_duration`**
- **`http_req_failed`**
- **`iterations`**
- **`vus`**
- **`vus_max`**
- **`checks`**

Each metric contains summary information such as:

- **average**
- **minimum**
- **maximum**
- **median**
- **percentiles** such as p(90), p(95)

---

# Example of What `handleSummary()` Receives Conceptually

The `data` object is large, but conceptually it looks like this:

```javascript
{
  metrics: {
    http_req_duration: {
      type: "trend",
      contains: "time",
      values: {
        avg: ...,
        min: ...,
        med: ...,
        max: ...,
        "p(90)": ...,
        "p(95)": ...
      }
    },
    iterations: {
      ...
    }
  }
}
```

You do **not** need to build this object yourself—k6 creates it and passes it automatically to `handleSummary()`.

---

# Why Use `handleSummary()`?

`handleSummary()` is useful when the default terminal output is not enough.

## Common use cases

- Save the final test report as **JSON**    
- Generate a custom **HTML report**
- Export results in a format required by another tool
- Create cleaner or smaller reports by selecting only important metrics
- Produce multiple outputs from one test run

---

# Important Characteristics of `handleSummary()`

## 1) It runs only at the end of the test

It does **not** run continuously during the test. It runs **once**, after the execution is complete.

## 2) It works with aggregated summary data

It uses the **final summary metrics**, not live per-second streaming data.

## 3) It is mainly for local/custom summary generation

It is useful when you want to control the final output yourself.

---

# Returning Multiple Outputs

One useful feature of `handleSummary()` is that you can return **multiple outputs at once**.

Example:

```javascript
export function handleSummary(data) {
	return {
		"summary.json": JSON.stringify(data, null, 2),
		stdout: "Custom summary generated successfully\n"
	};
}
```

### What this does:

- writes the summary to **`summary.json`**    
- also prints a custom message to the terminal using `stdout`

---

# Pretty-Printed JSON

In your current example:

```javascript
JSON.stringify(data)
```

the JSON will be stored in a compact single-line format.

If you want it to be more readable, use:

```javascript
JSON.stringify(data, null, 2)
```

### Example

```javascript
export function handleSummary(data) {
	return {
		"summary.json": JSON.stringify(data, null, 2)
	};
}
```

This formats the JSON nicely with indentation.

    - save the summary to a **JSON file**
