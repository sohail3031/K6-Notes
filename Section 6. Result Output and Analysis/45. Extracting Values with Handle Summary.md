The `handleSummary()` function in k6 can do more than just write the full summary to a file. It can also be used to **extract specific metric values** from the aggregated summary data and print or store only the information you care about.

In this example, we extract the **median iteration duration** from the summary object and print a custom message to the console.

---

## What this example does

The script performs a normal HTTP request in the `default` function:

```javascript
http.get("https://test.k6.io");
```

After the test run completes, k6 calls the `handleSummary(data)` function and passes it the aggregated results object.

Inside `handleSummary()`:

- we access the `iteration_duration` metric    
- extract its **median value**
- build a custom message string
- return that message to `stdout`

So instead of printing the full summary, the script prints only a **custom metric-based message**.

---

## Code

```javascript
import http from "k6/http";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	const medLatency = data.metrics.iteration_duration.values.med;
	const latencyMessage = `The median latency was ${medLatency}\n`;

	return {
		stdout: latencyMessage
	};
}
```

---

# Step-by-step explanation

## 1. Execute the request

```javascript
export default function() {
	http.get("https://test.k6.io");
}
```

This is the test logic.  
Each iteration sends a GET request to the given URL.

---

## 2. k6 passes the aggregated summary data to `handleSummary()`

```javascript
export function handleSummary(data) {
```

At the end of the test, k6 automatically calls this function and passes a `data` object containing all aggregated test metrics.

This `data` object includes metrics such as:

- `http_req_duration`
- `iteration_duration`
- `http_reqs`
- `checks`
- `data_sent`
- `data_received`

and more.

---

## 3. Extract the median iteration duration

```javascript
const medLatency = data.metrics.iteration_duration.values.med;
```

This line reads the **median (`med`) value** of the `iteration_duration` metric.

### Breakdown:

- `data.metrics` → contains all collected metrics    
- `iteration_duration` → total time taken for one full iteration of the `default()` function
- `values.med` → the median value of that metric

So this line gives you the **median iteration duration** for the whole test.

---

## 4. Create a custom message

```javascript
const latencyMessage = `The median latency was ${medLatency}\n`;
```

This creates a formatted output string.

Example output:

```text
The median latency was 245.67
```

---

## 5. Return the message to `stdout`

```javascript
return {
	stdout: latencyMessage
};
```

This tells k6 to print the custom message to the terminal.

---

# Important clarification: iteration duration vs request duration

In this example, the code uses:

```javascript
data.metrics.iteration_duration.values.med
```

This is the **median iteration duration**, not the raw HTTP request duration.

## `iteration_duration`

Measures the total time for one full iteration of the `default()` function, including:

- HTTP request time
- sleeps
- JavaScript execution
- any logic inside the iteration

## `http_req_duration`

Measures only the HTTP request duration, including:

- sending request
- waiting for response
- receiving response

So if you want the **median HTTP response time**, use:

```javascript
const medLatency = data.metrics.http_req_duration.values.med;
```

# Better wording for the output message

Since the current script extracts `iteration_duration`, the message:

```javascript
The median latency was ...
```

is a little misleading.

A more accurate version would be:

```javascript
const medDuration = data.metrics.iteration_duration.values.med;
const message = `The median iteration duration was ${medDuration} ms\n`;
```

---

# Recommended corrected version

If you want to report **iteration duration**, use this:

```javascript
import http from "k6/http";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	const medDuration = data.metrics.iteration_duration.values.med;
	const message = `The median iteration duration was ${medDuration} ms\n`;

	return {
		stdout: message
	};
}
```

---

# If you want HTTP request latency instead

If your goal is to print the **median HTTP request latency**, use `http_req_duration` instead:

```javascript
import http from "k6/http";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	const medLatency = data.metrics.http_req_duration.values.med;
	const message = `The median HTTP request latency was ${medLatency} ms\n`;

	return {
		stdout: message
	};
}
```

---

# When this approach is useful

Extracting values inside `handleSummary()` is useful when you want to:

- print only one or two important metrics instead of the full summary    
- generate a custom pass/fail message
- create compact CI/CD output
- write selected metrics to a custom report
- export only the values needed by another tool

---

# Key takeaway

`handleSummary()` can be used not only to **store full summaries** but also to **extract specific metric values** from the summary object and present them in a custom format.

In this example:

- the test runs normally    
- k6 aggregates all metrics
- `handleSummary()` extracts the median value from `iteration_duration`
- a custom message is printed to the console
