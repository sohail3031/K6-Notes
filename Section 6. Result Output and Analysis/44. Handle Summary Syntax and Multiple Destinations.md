In k6, the `handleSummary()` function lets you **customize where and how the test summary is written** after the test finishes. Instead of relying only on the default console output, you can send the summary to **multiple destinations** such as:

- the terminal (`stdout`)    
- an error stream (`stderr`)
- a JSON file
- an HTML file
- any other custom file path

This is useful when you want to generate **machine-readable reports**, **human-friendly summaries**, or **multiple report formats** from a single test run.

---

## How `handleSummary()` works

k6 expects `handleSummary()` to **return an object of key-value pairs**:

- **Key** → destination of the output    
- **Value** → content to write to that destination

### Supported keys

The keys can be:

- `"stdout"` → print to the console
- `"stderr"` → print to the error stream
- `"relative/or/absolute/file/path"` → write to a file

### Supported values

The value for each key can be:

- a **string**
- an **ArrayBuffer**

That means you can output:

- a **formatted text summary**
- the **raw JSON summary**
- a **custom HTML report**
- or any other custom format you generate yourself

---

## Example 1: Write summary to the console and a JSON file

This example prints a nicely formatted test summary to the terminal and also stores the full summary in a `summary.json` file.

```javascript
import http from "k6/http";
import { textSummary } from "https://jslib.k6.io/k6-summary/0.0.1/index.js";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	return {
		stdout: textSummary(data, { indent: " ", enableColors: true }), // show summary in console
		"summary.json": JSON.stringify(data), // save summary as JSON
	};
}
```

---

## What this does

### `textSummary(data, { indent: " ", enableColors: true })`

This generates a **readable summary** similar to the default k6 output, but you can control formatting.

### `"summary.json": JSON.stringify(data)`

This saves the complete summary object to a JSON file so it can be reused by:

- dashboards
- reporting tools
- CI/CD pipelines
- custom scripts

---

## Example 2: Print raw JSON to the console

If you want the full summary object printed directly to the console in JSON format, you can do this:

```javascript
import http from "k6/http";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	return {
		stdout: JSON.stringify(data, null, 2), // print JSON summary to console
		"summary.json": JSON.stringify(data),  // save JSON summary to file
	};
}
```

### `JSON.stringify(data, null, 2)`

This pretty-prints the JSON with indentation, making it easier to read in the terminal.

---

## Important note about duplicate keys

In JavaScript objects, **duplicate keys are not allowed**.  
So this version is **incorrect**:

```javascript
return {
	"stdout": textSummary(data, { indent: " ", enableColors: true }),
	"stdout": JSON.stringify(data, null, 2),
	"summary.json": JSON.stringify(data)
};
```

Because the second `"stdout"` will overwrite the first one.

### If you want both a text summary and JSON output:

- send the **text summary to `stdout`**    
- save the **JSON to a file**

---

## Example 3: Output to multiple destinations including HTML

You can also generate a custom HTML report and save it alongside the JSON report.

```javascript
import http from "k6/http";

export default function() {
	http.get("https://test.k6.io");
}

export function handleSummary(data) {
	return {
		stdout: JSON.stringify(data, null, 2), // print JSON summary to console
		"summary.json": JSON.stringify(data),  // save JSON summary to file
		"summary.html": generateHTMLSummary(data), // save HTML summary
	};
}

function generateHTMLSummary(data) {
	let html = `<html><body><h1>Test Summary</h1>`;
	html += `<pre>${JSON.stringify(data, null, 2)}</pre>`;
	html += `</body></html>`;

	return html;
}
```

# Output destinations supported by `handleSummary()`

## 1. Standard output (`stdout`)

Used to display the summary in the terminal.

```javascript
stdout: textSummary(data, { indent: " ", enableColors: true })
```

or

```javascript
stdout: JSON.stringify(data, null, 2)
```

---

## 2. JSON file

Useful for storing structured test results for later analysis.

```javascript
"summary.json": JSON.stringify(data)
```

---

## 3. HTML file

Useful when you want a browser-friendly report.

```javascript
"summary.html": generateHTMLSummary(data)
```

---

## 4. Custom file path

You can write the summary to any folder path.

```javascript
"reports/k6-summary.json": JSON.stringify(data)
```

---

# Structure of the `handleSummary()` return object

General syntax:

```javascript
export function handleSummary(data) {
	return {
		stdout: "some formatted text",
		"summary.json": JSON.stringify(data),
		"summary.html": "<html>...</html>"
	};
}
```

# Common use cases

## 1. Console + JSON file

Best when you want a readable console output and a structured report for automation.

```javascript
return {
	stdout: textSummary(data, { indent: " ", enableColors: true }),
	"summary.json": JSON.stringify(data),
};
```

---

## 2. JSON only

Useful for CI/CD or when another system will process the results.

```javascript
return {
	"summary.json": JSON.stringify(data),
};
```

---

## 3. Console + JSON + HTML

Useful when you want:

- quick console visibility    
- machine-readable JSON
- shareable HTML report

```javascript
return {
	stdout: textSummary(data, { indent: " ", enableColors: true }),
	"summary.json": JSON.stringify(data),
	"summary.html": generateHTMLSummary(data),
};
```

---

# Key takeaways

## `handleSummary()` is used to customize k6 test result output

It runs **after the test finishes** and receives the aggregated summary data.

## It must return an object

The returned object maps **destinations** to **content**.

## You can write to multiple destinations at once

For example:

- terminal
- JSON file
- HTML file

## Avoid duplicate keys

If you define `"stdout"` twice, only the last one will be used.
