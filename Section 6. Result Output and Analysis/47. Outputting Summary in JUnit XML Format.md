## Overview

k6 allows you to export the final test summary in **JUnit XML format**, which is especially useful for integrating performance test results with **CI/CD pipelines**, **test reporting dashboards**, and tools that support **JUnit-style reports**.

A JUnit XML report can be consumed by tools such as:

- **Jenkins**    
- **GitHub Actions**
- **GitLab CI**
- **Azure DevOps**
- other test reporting frameworks that understand JUnit output

---

## Key Idea

The `handleSummary()` function can be used to transform the aggregated k6 results into **JUnit XML** and save them to a file.

To do this, k6 uses the **`jUnit()`** helper from the `k6-summary` library.

---

## Example Code

```javascript
import { jUnit } from "https://jslib.k6.io/k6-summary/0.0.2/index.js";
import k6example from "https://raw.githubusercontent.com/grafana/k6/master/examples/thresholds_readme_example.js";

export default k6example;

export const options = {
	vus: 5,
	iterations: 10,
	thresholds: {
		http_req_duration: ["p(95)<200"],
	}
};

export function handleSummary(data) {
	return {
		"junit.xml": jUnit(data)
	};
}
```

---

# Explanation

## 1) Importing the JUnit helper

```javascript
import { jUnit } from "https://jslib.k6.io/k6-summary/0.0.2/index.js";
```

- `jUnit()` is a helper function that converts the k6 summary data into **JUnit XML format**.    

---

## 2) Importing a sample test script

```javascript
import k6example from "https://raw.githubusercontent.com/grafana/k6/master/examples/thresholds_readme_example.js";
```

- This imports an example k6 test script from the official k6 repository.    
- Instead of writing a new `default` function locally, we reuse the imported script.

```javascript
export default k6example;
```

- This sets the imported script as the **default test function**.    

---

## 3) Defining test options

```javascript
export const options = {
	vus: 5,
	iterations: 10,
	thresholds: {
		http_req_duration: ["p(95)<200"],
	}
};
```

### Meaning of each option:

- **`vus: 5`** → run the test with **5 virtual users**    
- **`iterations: 10`** → execute a total of **10 iterations**
- **`thresholds`** → define performance expectations

### Threshold used here:

```javascript
http_req_duration: ["p(95)<200"]
```

This means:

- **95% of HTTP requests must complete in under 200 ms**

If the threshold is not met, the test will be marked as **failed** in the summary.

---

## 4) Generating the JUnit XML report

```javascript
export function handleSummary(data) {
	return {
		"junit.xml": jUnit(data)
	};
}
```

- `handleSummary(data)` runs **after the test finishes**    
- `data` contains the **aggregated k6 test results**
- `jUnit(data)` converts that summary into **JUnit XML**
- The returned object tells k6 to save the XML content into a file named **`junit.xml`**

---

# What happens when you run the script?

Run:

```bash
k6 run output-junit.js
```

### Execution flow:

1. k6 runs the imported test script    
2. Metrics such as request duration, iterations, checks, and thresholds are collected
3. After the test completes, `handleSummary()` is executed
4. k6 creates a file named **`junit.xml`**
5. That file contains the test result in **JUnit XML format**

---

# Why use JUnit XML output?

## Benefits

- Easy integration with **CI/CD pipelines**    
- Can be displayed in **test reporting dashboards**
- Useful for **automated pass/fail reporting**
- Makes performance test results look similar to functional test reports

---

# Typical Use Cases

Use JUnit XML output when you want to:

- include k6 results in **Jenkins test reports**    
- publish test results in **GitHub Actions / GitLab CI**
- combine performance results with other automated test results
- store machine-readable reports for later analysis

# Summary

- `handleSummary()` lets you customize the final k6 output    
- `jUnit(data)` converts k6 summary data into **JUnit XML**
- returning:

```javascript
{ "junit.xml": jUnit(data) }
```

	creates a **JUnit XML report file**

- this is very useful for **CI/CD integration** and **automated reporting**
