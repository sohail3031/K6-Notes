## Overview

So far, most k6 examples have focused on the **end-of-test summary** shown in the console or generated with `handleSummary()`.

But k6 can also **stream raw metrics continuously while the test is running**.  
This is useful when you want:

- **real-time monitoring**    
- **granular metric data**
- integration with **dashboards / monitoring systems**
- storing raw test events for later analysis

k6 supports streaming output to:

- **local files** such as **JSON** and **CSV**
- **external monitoring systems** such as InfluxDB, Prometheus, Grafana Cloud, etc.

---

# Key Idea

The `--out` flag is used to stream k6 metrics to another destination while the test is running.

General syntax:

```bash
k6 run --out <output-type>=<destination> script.js
```

Examples:

- stream to a **JSON file**    
- stream to a **CSV file**
- stream to **InfluxDB**
- stream to **Grafana Cloud**
- stream to **Prometheus-compatible backends**

---

# Example Test Script

```javascript
import http from "k6/http";
import { sleep } from "k6";

export let options = {
	vus: 10,
	duration: "30s"
};

export default function() {
	http.get("https://test.k6.io");
	sleep(1);
}
```

---

# What this script does

- runs with **10 virtual users**    
- executes for **30 seconds**
- each VU sends a request to `https://test.k6.io`
- sleeps for **1 second** after each iteration

While this test is running, k6 can stream the metrics generated by this script to a file or external system.

---

# 1) Streaming Output to CSV

## Command

```bash
k6 run --out csv=output.csv <file_name.js>
```

## Meaning

- `--out csv=output.csv`    
- tells k6 to stream metrics into a **CSV file**
- the file is updated while the test is running

### Result

k6 creates a file like:

```text
output.csv
```

This file contains metric samples generated during execution.

---

# 2) Streaming Output to JSON

## Command

```bash
k6 run --out json=output.json <file_name.js>
```

## Meaning

- `--out json=output.json`    
- tells k6 to stream metrics into a **JSON file**
- the file is written incrementally as the test runs

### Result

k6 creates:

```text
output.json
```

This file contains raw metric events and data points in JSON format.

---

# Important Clarification: Summary vs Streaming Output

## End-of-test summary

This is what you normally see in the console after the test finishes:

- average response time    
- p(95)
- total iterations
- checks, errors, etc.

This summary is **aggregated output**.

---

## Streaming output

Streaming output is different:

- it writes **raw metric data continuously during the test**    
- useful for **live dashboards** and **real-time analysis**
- not just the final summary

So:

- **`handleSummary()`** → final aggregated results after test completion
- **`--out`** → raw metrics streamed during execution

---

# What kind of data gets streamed?

Depending on the output format/backend, streamed data can include:

- request timings    
- iterations
- checks
- VU metrics
- data points over time
- metric samples for dashboards and monitoring tools

This is more detailed than the final summary because it preserves time-based metric data.

Good for:

## JSON

Use:
