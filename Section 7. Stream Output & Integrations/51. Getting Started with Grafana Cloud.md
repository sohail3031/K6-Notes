This lecture is the **setup bridge** between:

- **K6 generating metrics**    
- **Prometheus receiving those metrics**
- **Grafana Cloud storing and visualizing them**

---

## Goal of this lecture

Understand how to use **Grafana Cloud** as a hosted observability platform so that **k6 test metrics** can be sent to a **Prometheus-compatible metrics backend** and then visualized in **Grafana dashboards**.

---

# 1) What is Grafana Cloud?

**Grafana Cloud** is a hosted observability platform from [Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/grafana-cloud-prometheus/?utm_source=chatgpt.com) that provides managed services for:

- **Metrics** → Prometheus-compatible storage
- **Logs** → Loki
- **Traces** → Tempo
- **Dashboards / visualization** → Grafana
- **Alerting** → unified alerting and notifications

### Why it matters for K6

Instead of storing performance metrics only in the terminal or local files, you can push them to Grafana Cloud and:

- monitor test results in near real time
- keep historical test data
- build dashboards
- compare multiple test runs
- correlate performance test metrics with application/infrastructure metrics

---

# 2) What role does Prometheus play here?

Prometheus is the **metrics storage/query layer** in this setup.

For K6 + Grafana Cloud, the common idea is:

## Flow

**k6 test**  
→ sends metrics to **Grafana Cloud Prometheus remote write endpoint**  
→ metrics are stored in Grafana Cloud’s Prometheus-compatible backend  
→ **Grafana dashboards / Explore** are used to visualize and query them ([Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/grafana-cloud-prometheus/?utm_source=chatgpt.com "Grafana Cloud Prometheus | Grafana k6 documentation"))

---

# 3) What do you need from Grafana Cloud?

To connect k6 to Grafana Cloud Prometheus, you typically need **three pieces of information** from your Grafana Cloud Prometheus service:

## Required connection details

1. **Remote Write Endpoint URL**    
    - the Prometheus remote write URL where k6 will push metrics
2. **Username / Instance username**
    - used for authentication
3. **Access Policy Token / API token**
    - used as the password
    - should have permission to write metrics (for example `metrics:write`) ([Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/grafana-cloud-prometheus/?utm_source=chatgpt.com "Grafana Cloud Prometheus | Grafana k6 documentation"))

# 4) High-level setup steps in Grafana Cloud

## Step 1 — Create / log into Grafana Cloud

Sign in to your Grafana Cloud account.

## Step 2 — Open your Prometheus / Metrics service details

Inside your stack, go to the **Prometheus / Metrics** section and open the service details.

## Step 3 — Copy the connection details

From the Prometheus details page, note:

- **Remote Write Endpoint**    
- **Username**
- **Instance / service details**

## Step 4 — Generate an access token

Create a Grafana Cloud **Access Policy Token** (API token) with metric write permission.  
This token acts as the **password** when k6 sends data. ([Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/grafana-cloud-prometheus/?utm_source=chatgpt.com "Grafana Cloud Prometheus | Grafana k6 documentation"))

---

# 5) Important security note

Treat the **API token / access policy token** like a password:

- do **not** hardcode it in public repos    
- do **not** share it
- prefer environment variables or secret managers

# 6) How k6 sends metrics to Grafana Cloud Prometheus

k6 can send metrics to a Prometheus-compatible backend using the **Prometheus Remote Write output**.

The current Grafana k6 docs show using the **experimental Prometheus remote write output** with environment variables like these: ([Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/prometheus-remote-write/?utm_source=chatgpt.com "Prometheus remote write | Grafana k6 documentation"))

```bash
K6_PROMETHEUS_RW_USERNAME=<USERNAME>
K6_PROMETHEUS_RW_PASSWORD=<ACCESS_POLICY_TOKEN>
K6_PROMETHEUS_RW_SERVER_URL=<REMOTE_WRITE_ENDPOINT>
k6 run -o experimental-prometheus-rw script.js
```

---

# 7) Meaning of the key environment variables

## `K6_PROMETHEUS_RW_SERVER_URL`

The **remote write endpoint URL** of your Grafana Cloud Prometheus service.

## `K6_PROMETHEUS_RW_USERNAME`

The Grafana Cloud Prometheus username / instance username.

## `K6_PROMETHEUS_RW_PASSWORD`

The Grafana Cloud access policy token (used like a password).

## `-o experimental-prometheus-rw`

Tells k6 to stream metrics using the **Prometheus Remote Write output**.

---

# 8) Example command

Here’s the clean form of the command you’d use after collecting your Grafana Cloud credentials:

```bash
K6_PROMETHEUS_RW_USERNAME=YOUR_USERNAME \
K6_PROMETHEUS_RW_PASSWORD=YOUR_ACCESS_POLICY_TOKEN \
K6_PROMETHEUS_RW_SERVER_URL=YOUR_REMOTE_WRITE_ENDPOINT \
k6 run -o experimental-prometheus-rw script.js
```

### What happens when this runs?

- k6 executes the load test    
- k6 converts test metrics into Prometheus-style time series
- those metrics are pushed to the remote write endpoint
- Grafana Cloud stores them
- you can then query them in Grafana dashboards / Explore ([Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/prometheus-remote-write/?utm_source=chatgpt.com "Prometheus remote write | Grafana k6 documentation"))

---

# 9) Optional: tag each test run

A very useful practice is to add a unique **test ID** so different test runs are easy to separate in dashboards.

Example:

```bash
K6_PROMETHEUS_RW_USERNAME=YOUR_USERNAME \
K6_PROMETHEUS_RW_PASSWORD=YOUR_ACCESS_POLICY_TOKEN \
K6_PROMETHEUS_RW_SERVER_URL=YOUR_REMOTE_WRITE_ENDPOINT \
k6 run -o experimental-prometheus-rw --tag testid=run_001 script.js
```

This helps when:

- comparing multiple runs    
- filtering a specific execution in Grafana
- keeping dashboard panels cleaner ([Grafana Labs](https://grafana.com/docs/k6/latest/results-output/real-time/grafana-cloud-prometheus/?utm_source=chatgpt.com "Grafana Cloud Prometheus | Grafana k6 documentation"))

Once metrics are pushed successfully, you can use Grafana Cloud to:

    - request duration

Use Grafana Explore / PromQL to query k6 metrics.

## Correlate metrics

Compare k6 performance data with:

- DB metrics

# 11) Key concept: Prometheus Remote Write

This lecture is really introducing the idea that **Grafana Cloud doesn’t need to scrape k6 directly** in this setup.  
Instead, **k6 pushes metrics to the Prometheus remote write endpoint**.

So the model is:

## Traditional Prometheus

Prometheus scrapes `/metrics` endpoints

## K6 → Grafana Cloud setup

k6 **pushes** metrics using **Prometheus Remote Write**

That’s the important architectural distinction for your notes.
