This section is basically the bridge from **“K6 generates metrics”** to **“how we monitor and visualize those metrics in real time.”**

## Key takeaway

K6 can do more than just print a summary at the end of a test:

- it can **stream metrics continuously**
- those metrics can be sent to monitoring systems
- **Prometheus** can collect/store time-series metrics
- **Grafana** can visualize those metrics in dashboards

---

## Why stream K6 metrics to external tools?

Streaming metrics gives you **real-time visibility** during a performance test instead of waiting until the test ends.

### Benefits

- detect issues while the test is running    
- monitor response times, throughput, and failures live
- correlate K6 load with backend/system metrics
- build dashboards and alerts
- keep historical performance data

---

# Prometheus

## What is Prometheus?

**Prometheus** is an open-source **monitoring and alerting toolkit** used to collect and store metrics as **time-series data**.

### Important points

- originally developed by **SoundCloud**    
- now part of the **Cloud Native Computing Foundation (CNCF)**
- widely used for monitoring applications, servers, containers, and infrastructure
- works very well with modern cloud-native systems

---

## Prometheus architecture

Prometheus works by collecting metrics from endpoints and storing them as time-series data.

### Main components

## 1) Prometheus Server

The main Prometheus service.

**Responsibilities:**

- scrapes metrics from configured targets    
- stores metrics in its database
- lets you query those metrics later

---

## 2) Time Series Database

Prometheus stores metrics as **time-series data**, meaning values are stored with timestamps.

Example:

- request count over time    
- response time over time
- CPU usage over time

This is useful because performance testing is all about **how values change during the run**.

---

## 3) Exporters

Exporters are small tools/services that expose metrics from systems that Prometheus cannot read directly.

### Example

If you want Prometheus to monitor:

- OS metrics    
- database metrics
- container metrics
- application metrics

you often use an exporter to expose those metrics in Prometheus format.

---

## 4) Metrics Endpoint

Prometheus pulls metrics from an **HTTP endpoint**.

That endpoint exposes data in a format Prometheus understands.

Example conceptually:

- application exposes `/metrics`    
- Prometheus scrapes `/metrics`
- data is stored in Prometheus

---

## 5) Service Discovery

Prometheus can dynamically discover targets instead of requiring every endpoint to be manually configured.

This is useful in:

- cloud systems    
- containerized environments
- microservices
- dynamic infrastructure

---

# Grafana

## What is Grafana?

**Grafana** is an open-source **analytics and visualization platform**.

It is commonly used on top of Prometheus to display metrics in dashboards.

### Grafana helps you:

- create dashboards    
- visualize performance trends
- compare multiple metrics together
- set alerts
- analyze bottlenecks during load tests

---

# Prometheus vs Grafana

A very common interview question is:

## What is the difference between Prometheus and Grafana?

### Prometheus

- **collects**    
- **stores**
- **queries** time-series metrics

### Grafana

- **visualizes**
- **analyzes**
- **displays dashboards and charts** using data from Prometheus (or other data sources)

### Simple way to remember

- **Prometheus = metrics collection + storage**
- **Grafana = dashboards + visualization**

---

# How K6 fits into this

When you run performance tests in K6, it generates metrics such as:

- request duration    
- failed requests
- iterations
- VUs
- throughput
- latency percentiles

Instead of only seeing those in the terminal or summary file, you can stream them to a monitoring stack such as:

- Prometheus
- Grafana Cloud
- InfluxDB
- Datadog
- New Relic
- Elasticsearch
- CloudWatch
- Kafka
- StatsD
- others

---

# K6 + Prometheus + Grafana flow

A simple mental model is:

## Flow

**K6 test run**  
→ generates performance metrics  
→ sends/streams metrics to a backend such as **Prometheus / Grafana Cloud**  
→ **Grafana** reads those metrics  
→ dashboards display live charts, trends, and alerts

---

# Why this is useful in performance testing

Using K6 with Prometheus and Grafana helps you answer questions like:

- At what point did response time spike?    
- Did error rate increase when VUs increased?
- What was throughput during the peak stage?
- How did latency behave during ramp-up vs ramp-down?
- Did the backend CPU/memory/database load increase along with K6 traffic?
