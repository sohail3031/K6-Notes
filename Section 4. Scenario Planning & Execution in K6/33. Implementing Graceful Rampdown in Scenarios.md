## **What is graceful ramp down?**

**Graceful ramp down** is the time k6 gives to virtual users (VUs) to finish their **current iteration** when the load is decreasing in a **ramping-vus scenario**.

Instead of immediately killing VUs when scaling down:  
👉 k6 allows them to complete work first  
👉 then gradually removes them

---

## **When does it apply?**

It only applies when:

- using **`ramping-vus` executor**
- VUs are **decreasing between stages**

Example:

- 10 VUs → 0 VUs
- k6 waits before killing extra VUs

---

## **Key idea**

| Concept          | Meaning                                                   |
| ---------------- | --------------------------------------------------------- |
| Ramp down        | Reducing VUs between stages                               |
| gracefulRampDown | Time allowed to finish active iterations during reduction |

---

## **Correct Code**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	scenarios: {
		ramping_load: {
			executor: "ramping-vus",
			startVUs: 1,
			stages: [
				{ duration: "10s", target: 10 },
				{ duration: "10s", target: 0 }
			],
			gracefulRampDown: "5s"
		}
	}
};

export default function () {
	http.get("https://test.k6.io");
	sleep(1);
}
```

---

## **Why this is correct**

✔ `ramping-vus` supports staged load changes  
✔ `gracefulRampDown` ensures clean VU reduction  
✔ prevents cutting active requests during scale-down  
✔ improves accuracy of performance metrics

---

## **What happens step-by-step**

### **Stage 1 (Ramp up)**

- 1 → 10 VUs
- traffic increases gradually

### **Stage 2 (Ramp down)**

- 10 → 0 VUs
- k6 starts removing users

### **Graceful ramp down phase**

- k6 waits **5 seconds**
- active iterations are allowed to finish
- then remaining VUs are stopped    

---

## **Why graceful ramp down is important**

Without it:

- requests may be cut mid-execution ❌
- partial transactions may occur ❌
- inaccurate latency metrics ❌

With it:

- clean shutdown ✔
- realistic user behavior ✔
- stable results ✔

---

## **Graceful Stop vs Graceful Ramp Down (very important)**

| Feature          | Applies to       | When            |
| ---------------- | ---------------- | --------------- |
| gracefulStop     | Any executor     | End of scenario |
| gracefulRampDown | ramping-vus only | Between stages  |

---

## **Simple analogy**

- **gracefulStop** → end of test
- **gracefulRampDown** → slowing traffic before exit

Like:  
👉 closing a shop

- gracefulRampDown = stopping new customers gradually
- gracefulStop = finishing last customers before shutting door

---

## **Final takeaway**

- Used only in **ramping-vus**
- Helps avoid abrupt VU termination during load decrease
- Ensures smoother, more realistic performance transitions
