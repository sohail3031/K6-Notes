# Dropped Iterations:
- **Dropped Iterations:** Instances where k6 fails to start new iterations as expected.
- **Cause:** Typically due to insufficient resources or exceeding the maximum number of Virtual Users (VUs).

# Code:

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	scenarios: {
		high_rate: {
			executor: "constant-arrival-rate",
			rate: 100, // high iteration rate
			timeUnit: "1s",
			duration: "20s",
			preAllocatedVUs: 10,
			maxVUs: 20
		}
	}
};

export default function() {
	http.get("https://test.k6.io");
	
	sleep(1);
}
```

**Note:** When you run the above code, you can see a warning message showing insufficient virtual users and in the output you can notice values for dropped_iterations.

# Reasons for Dropped Iterations
1. **Insufficient Resources:**
	- **CPU and Memory:** The system may lack sufficient CPU or memory resources to handle the desired iteration rate.
	- **Network Bandwidth:** Limited bandwidth can lead to dropped iterations if the system can't handle the traffic volume.
2. **Exceeding Max VUs:** 
	- **Pre-Allocated VUs:** Insufficient pre-allocated VUs may result in dropped iterations.
	- **Max VUs:** If required VUs exceed the specified maximum (maxVUs), k6 can't start new iterations.
3. **System Under Test Bottlenecks:**
	- **Backend Limitations:** High load may overwhelm backend systems (e.g. web servers, databases), causing delays and dropped iterations.
	- **Application Bottlenecks:** Performance bottlenecks within the application can lead to dropped iterations.

# What Dropped Iterations Signify
1. **Performance Bottlenecks:**
	- **Identification:** Dropped iterations highlight points where the system struggles with the desired load.
2. **Resource Limitations:**
	- **System Resources:** Indicates the need for more CPU, memory, or network bandwidth.
	- **Test Configuration:** Adjustments (e.g. increasing VUs) may be necessary.
3. **Test Reliability:**
	- **Accuracy:** Dropped iterations affect test result accuracy.
	- **Scalability:** Insights into system limits before performance degradation occur.
