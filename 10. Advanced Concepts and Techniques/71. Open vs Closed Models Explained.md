# Scheduling Models in K6
## 1.  **Closed Model:**
	- VU iteration starts sequentially.
	- Execution time of each iteration determines test duration.
	- Couped to iteration duration.
## 2. **Open Model:**
	- VUs arrive independently of iteration completion.
	- Decouples VU start from response times.
	- Ideal for large and complex tests.

# Open Model vs Closed Model
## Executors:
1. **Open Model Executors:**
	- constant-arrival-rate
	- ramping-arrival-rate
2. **Closed Model Executors:**
	- per-vu-iterations
	- constant-vus
	- ramping-vus

## Configuration Parameters:
 - **Open Model:** Focus on rate of arrival (e.g. rate, timeUnit, duration).
 - **Closed Model:** Focus on concurrency and iterations (e.g. vus, iterations).

# Pros & Cons
## Open Model:
- **Pros:** Realistic traffic simulation, easy to control arrival rate, scalable, good for throughput testing.
- **Cons:** Less control over concurrent users, potentially unpredictable load, complex analysis.

## Close Model:
- **Pros:** Precise control over concurrency, easier analysis, good for stress testing, consistent load.
- **Cons:** Less realistic for public web services, not suitable.

# Code:
**Code for Open Model:**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	scenarios: {
		open_nodel: {
			executor: "constant-arrival-rate",
			rate: 5, // 5 iterations per second
			timeUnit: "1s", // rate per second
			duration: "30s",
			preAllocatedVUs: 5, // initial pool of vus
			maxVUs: 10 // max number of vus
		}
	}
};

export default function() {
	http.get("https://test.k6.io");
	
	sleep(1);
}
```

**Code for Closed Model:**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	scenarios: {
		closed_model: {
			executor: "per-vu-iterations",
			vus: 5, // number of vus
			iterations: 10 // number of iterations per vu
		}
	}
};

export default function() {
	http.get("https://test.k6.io");
	
	sleep(1);
}
```

# Open Model Use Cases:
1. **Public Web Traffic Simulation:** Simulating user traffic to a public-facing website users are constantly arriving and interacting.
	- **Example:** Testing a news website during major events to handle traffic spikes.
2. **E-commerce Platforms:** Simulating continuous shopping activities on e-commerce site.
	- **Example:** Testing an online store during Black Friday sales.
3. **API Load Testing:** Generating a steady stream of API requests.
	- **Example:** Ensuring a public API can handle a constant rate of requests.
4. **Streaming Services:** Simulating continuous access to streaming content.
	- **Example:** Testing a video streaming service for a constant influx of viewers.

# Closed Model Use Cases:
1. **Internal Applications:** Testing with a fixed number of concurrent users.
	- **Example:** Ensuring performance of an HR portal during peak usage..
2. **Stress Testing:** Applying a controlled load to find performance bottlenecks.
	- **Example:** Stress testing a database under a fixed load of queries.
3. **Client-Server Applications:** Simulating fixed clients interacting with a server.
	- **Example:** Testing a multiplayer game server with a fixed number of players.
4. **SaaS Applications:** Testing with known user operations.
	- **Example:** Ensuring a project management tool can handle fixed team workloads.
5 **Load Testing for Capacity Planning:** Applying a fixed load to determine system capacity.
	- **Example:** Load testing a web server to find its user handling capacity.
