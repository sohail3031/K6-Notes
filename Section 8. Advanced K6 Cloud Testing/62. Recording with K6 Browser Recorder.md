## 🎯 What is a HAR File?

A **HAR (HTTP Archive) file** is a **JSON-based recording of browser network activity** during a user session.

👉 It captures everything your browser does while interacting with a website.

---

## 📦 What a HAR File Contains

A HAR file records detailed HTTP interactions such as:

- 🌐 HTTP requests & responses    
- 🧾 Headers (request & response)
- 📦 Payload/body data
- ⏱ Timing information
- 🔁 Redirects
- 🍪 Cookies

👉 This makes it extremely useful for performance testing and debugging.

---

## ⚙️ Why Use HAR Files in K6?

HAR files help you:

- Automatically generate test scripts    
- Reproduce real user behavior
- Reduce manual scripting effort
- Build complex load scenarios quickly

---

## 🚀 How to Record a Test in K6 Cloud

Follow these steps:

---

### 📍 Step 1: Create a New Test

Create a test using:

👉 Same flow as in **[[55. Using the K6 Cloud Script Builder]]**

- Go to **Test Builder**    
- Select **Create New Test**

---

### 📍 Step 2: Choose Recording Option

You will see options like:

- 📂 Import HAR File    
- 🎥 Record a Scenario

👉 Select **Record a Scenario**

---

### 📍 Step 3: Install Plugin (if needed)

If recording is not available:

- Install **Grafana K6 recording plugin**    
- Enable browser-based recording

---

### 📍 Step 4: Start Recording

Once enabled:

- Enter target URL 🌐    
- Click **Start Recording**
- Perform user actions (clicks, forms, navigation)

👉 All actions are recorded automatically

---

### 📍 Step 5: Stop Recording & Save

After finishing:

- Stop recording    
- Save the session as a HAR file
- Import into K6 test builder

---

## 🧪 What Happens After Recording?

Once imported:

- K6 automatically generates a script    
- Converts browser actions into HTTP requests
- Builds a full test scenario
- Opens in Test Builder for editing

---

## 🧠 Example Flow

User actions:

- Open website    
- Fill form
- Submit request

👉 K6 converts this into:

- HTTP GET/POST requests
- Headers + payloads
- Scenario logic
- Load test script

---

## ⚠️ Best Practices

- Use **realistic user flows**    
- Avoid overly fast navigation
- Don’t record unnecessary pages
- Focus on core business journey
- Prefer hybrid testing (UI + API)

---

## 🔄 API vs Browser Recording

| Type             | Use Case                    |
| ---------------- | --------------------------- |
| Browser Recorder | UI / user journey           |
| HAR-based script | Automated script generation |
| API testing      | Backend performance         |
