In addition to the **HTTP module**, K6 provides several other built-in modules that make performance testing easier and more powerful. These modules help with:

- creating **custom metrics**    
- performing **hashing / cryptographic operations**
- loading **test data from files**
- doing **encoding / decoding**
- parsing **HTML responses**
- getting **execution context information** such as VU ID and scenario name

The HTTP module is the most frequently used one, but these modules are also very important in real-world K6 scripting.

---

# **1. `k6/metrics` Module**

The **metrics module** is used to create **custom metrics** in K6.  
It is useful when you want to track values that are **not covered by built-in metrics**.

The common custom metric types are:

- **Counter**    
- **Gauge**
- **Trend**
- **Rate**

In this example, we are using a **Trend** metric.

---

## **Code**

```javascript
import { Trend } from "k6/metrics";

let myTrend = new Trend("my_trend");

export default function() {
	myTrend.add(1);
	myTrend.add(2);
	myTrend.add(3);
}
```

---

## **Explanation**

### **1) Import `Trend`**

```javascript
import { Trend } from "k6/metrics";
```

This imports the **Trend** class from the K6 metrics module.

---

### **2) Create a custom trend metric**

```javascript
let myTrend = new Trend("my_trend");
```

- `my_trend` is the name of the custom metric.
- K6 will show this metric in the test results.

---

### **3) Add values to the trend**

```javascript
myTrend.add(1);
myTrend.add(2);
myTrend.add(3);
```

These values are recorded into the trend metric.

Since this is a **Trend**, K6 will calculate statistics such as:

- **avg**
- **min**
- **max**
- **med**
- **p(90)**
- **p(95)**

So if the values are `1, 2, 3`, K6 will summarize them statistically in the output.

---

## **Use case**

Trend metrics are commonly used to store:

- response times
- DB query durations
- processing times
- any custom timing values

---

# **2. `k6/crypto` Module**

The **crypto module** is used for **cryptographic operations**, such as hashing.

It is commonly useful for:

- hashing request payloads
- generating signatures
- validating data
- authentication-related operations
- checksum comparisons

---

## **Code**

```javascript
import { sha256 } from "k6/crypto";

export default function()  {
	let hash = sha256("my-value", "hex");
	
	console.log(`SHA-256: ${hash}`);
}
```

---

## **Explanation**

### **1) Import `sha256`**

```javascript
import { sha256 } from "k6/crypto";
```

This imports the **SHA-256 hashing function**.

---

### **2) Generate hash**

```javascript
let hash = sha256("my-value", "hex");
```

This creates a SHA-256 hash of the string `"my-value"`.

- `"my-value"` → input string
- `"hex"` → output format

So the result will be the SHA-256 hash represented in **hexadecimal format**.

---

### **3) Print the hash**

```javascript
console.log(`SHA-256: ${hash}`);
```

This prints the generated SHA-256 value to the console.

---

## **Use case**

Crypto functions are useful when:

- APIs require request signing
- passwords/tokens need hashing
- you want to verify that content has not changed

---

# **3. `k6/data` Module**

The **data module** is used for **loading and managing test data**.  
A very common class from this module is **`SharedArray`**.

`SharedArray` is especially useful when:

- many VUs need access to the same data
- you want to load a file only once
- you want better memory efficiency

---

## **Code**

```javascript
import { SharedArray } from "k6/data";

const data = new SharedArray("some name", function() {
	const f= JSON.parse(open("./data.json"));
	
	return f;
});

export default function() {
	const element = data[Math.floor(Math.random() * data.length)];
	
	console.log(`Selected User: ${JSON.stringify(element)}`);
}
```

### **JSON file**

```json
[
	{
		"username": "user 1",
		"password": "test"
	},
	{
		"username": "user 2",
		"password": "test"
	}
]
```

---

## **Explanation**

### **1) Import `SharedArray`**

```javascript
import { SharedArray } from "k6/data";
```

This imports the **SharedArray** class.

---

### **2) Load JSON data**

```javascript
const data = new SharedArray("some name", function() {
	const f= JSON.parse(open("./data.json"));
	return f;
});
```

This creates a shared array called `"some name"`.

Inside it:

- `open("./data.json")` reads the JSON file
- `JSON.parse(...)` converts the JSON string into a JavaScript array/object
- the parsed data is returned and stored in `data`

So `data` becomes an array like:

```javascript
[
  { username: "user 1", password: "test" },
  { username: "user 2", password: "test" }
]
```

---

### **3) Pick a random element**

```javascript
const element = data[Math.floor(Math.random() * data.length)];
```

This selects a random user from the array.

If `data.length = 2`, then:

- `Math.random()` generates a random number between 0 and 1
- multiplying by `data.length` gives a value between 0 and 2
- `Math.floor()` converts it to either `0` or `1`

So a random record is selected.

---

### **4) Print selected user**

```javascript
console.log(`Selected User: ${JSON.stringify(element)}`);
```

This prints the randomly selected user object.

---

## **Use case**

This is very useful for:

- data-driven login tests
- selecting random users/products/orders
- loading large datasets only once for all VUs

---

# **4. `k6/encoding` Module**

The **encoding module** is used for encoding and decoding data.  
A common use case is **Base64 encoding/decoding**.

This is useful when:

- APIs expect Base64 encoded data
- credentials/tokens are stored in encoded form
- you need to verify encoded values

---

## **Code**

```javascript
import { check } from "k6";
import encoding from "k6/encoding";

export default function() {
	const str = "hello world";
	const enc = "aGVsbG8gd29ybGQ=";
	const buf = new Uint8Array([104, 101, 108, 108, 111, 32, 119, 111, 114, 108, 100]).buffer;
	
	check(null, {
		"is encoding string correct": () => encoding.b64encode(str) === enc,
		"is encoding ArrayBuffer correct": () => encoding.b64encode(buf) === enc
	});
}
```

---

## **Explanation**

### **1) Import encoding module**

```javascript
import encoding from "k6/encoding";
```

This imports the encoding utilities.

---

### **2) Define plain text and expected Base64**

```javascript
const str = "hello world";
const enc = "aGVsbG8gd29ybGQ=";
```

- `str` → original string
- `enc` → expected Base64 encoded value of `"hello world"`

---

### **3) Create an ArrayBuffer**

```javascript
const buf = new Uint8Array([104, 101, 108, 108, 111, 32, 119, 111, 114, 108, 100]).buffer;
```

These ASCII values represent the text `"hello world"`.

So `buf` is an ArrayBuffer version of the same text.

---

### **4) Validate Base64 encoding**

```javascript
check(null, {
	"is encoding string correct": () => encoding.b64encode(str) === enc,
	"is encoding ArrayBuffer correct": () => encoding.b64encode(buf) === enc
});
```

This performs two checks:

#### **Check 1**

```javascript
encoding.b64encode(str) === enc
```

Encodes the string `"hello world"` to Base64 and compares it to the expected value.

#### **Check 2**

```javascript
encoding.b64encode(buf) === enc
```

Encodes the ArrayBuffer and compares it to the same expected Base64 value.

If both match, both checks pass.

---

## **Use case**

Encoding is useful for:

- handling tokens or credentials
- preparing payloads for APIs
- validating encoded data returned by the system

---

# **5. `k6/html` Module**

The **HTML module** is used to **parse and inspect HTML responses**.

This is useful when:

- testing websites (not just APIs)
- extracting titles, links, forms, or other page elements
- validating that certain content exists in the page

---

## **Code**

```javascript
import http from "k6/http";
import { parseHTML } from "k6/html";

export default function() {
	let res = http.get("https://test.k6.io");
	let doc = parseHTML(res.body);
	let title = doc.find("title").text();
	
	console.log(`Page Title: ${title}`);
}
```

---

## **Explanation**

### **1) Send HTTP request**

```javascript
let res = http.get("https://test.k6.io");
```

This fetches the HTML page.

---

### **2) Parse the HTML body**

```javascript
let doc = parseHTML(res.body);
```

- `res.body` contains the raw HTML response
- `parseHTML()` converts it into a document object that can be queried

---

### **3) Find the title**

```javascript
let title = doc.find("title").text();
```

This finds the `<title>` element in the HTML and extracts its text.

For example, if the page contains:

```html
<title>Demo Website for Load Testing</title>
```

then `title` will become:

```javascript
"Demo Website for Load Testing"
```

---

### **4) Print the title**

```javascript
console.log(`Page Title: ${title}`);
```

This prints the extracted page title.

---

## **Use case**

HTML parsing is useful when:

- validating page titles
- checking if text appears in the UI
- extracting CSRF tokens / hidden fields from pages
- verifying content returned by a web application

---

# **6. `k6/execution` Module**

The **execution module** gives information about the **current execution context** of the script.

This is useful for:

- debugging
- logging VU-specific information
- identifying which scenario or VU encountered an issue

---

## **Code**

```javascript
import { vu, scenario } from "k6/execution";

export default function() {
	console.log(`VU ID: ${vu.idInTest}`);
	console.log(`Scenario Name: ${scenario.name}`);
}
```

---

## **Explanation**

### **1) Import execution info**

```javascript
import { vu, scenario } from "k6/execution";
```

This imports:

- **`vu`** → information about the current virtual user
- **`scenario`** → information about the currently running scenario

---

### **2) Print VU ID**

```javascript
console.log(`VU ID: ${vu.idInTest}`);
```

This prints the ID of the current virtual user.

Example output:

```javascript
VU ID: 3
```

This means the code is currently being executed by VU number 3.

---

### **3) Print scenario name**

```javascript
console.log(`Scenario Name: ${scenario.name}`);
```

This prints the name of the currently running scenario.

If you are only using the default scenario, it may print:

```javascript
Scenario Name: default
```

---

## **Use case**

Execution info is useful when:

- debugging multi-scenario tests
- logging which VU failed
- tracing errors back to a specific execution context

# **Summary of Built-in Modules Covered**

| Module             | Purpose                            | Example Use                            |
| ------------------ | ---------------------------------- | -------------------------------------- |
| **`k6/metrics`**   | Create custom metrics              | Record response times, custom counters |
| **`k6/crypto`**    | Hashing / cryptographic operations | SHA-256 hashing, signatures            |
| **`k6/data`**      | Load and share test data           | Read JSON/CSV test users               |
| **`k6/encoding`**  | Encode/decode data                 | Base64 encoding of tokens or strings   |
| **`k6/html`**      | Parse HTML responses               | Extract page title, verify UI content  |
| **`k6/execution`** | Get VU/scenario execution info     | Debugging and logging                  |

---

# **Key takeaway**

K6 is not just about sending HTTP requests. These built-in modules help you build **realistic, maintainable, and powerful performance tests** by supporting:

- **custom measurements**
- **data-driven testing**
- **encoding / hashing**
- **HTML content validation**
- **execution context debugging**
