# **1. K6 Test Lifecycle Overview**

A k6 test script goes through **4 lifecycle phases**:

1. **Init**    
2. **Setup**
3. **VU (Virtual User) code execution**
4. **Teardown**

These phases help organize a performance test into:

- initialization,
- test data preparation,
- actual load execution,
- and cleanup.

---

# **2. Init Phase**

The **Init phase** is the first phase of the k6 lifecycle.

### **What happens in Init?**

This phase is used for things such as:

- importing modules
- defining the `options` object
- loading files
- declaring constants and helper functions
- setting global variables

### **Important points**

- It runs **before any VU starts**
- It is required because the script must first be initialized
- It is **not the place for HTTP requests** to prepare shared test data for the run
- It is mainly used for configuration and script setup

---

# **3. Setup Phase**

The **Setup phase** runs **once before the VUs begin executing the test**.

### **What is it used for?**

Setup is used for:

- creating test data
- generating auth tokens
- reading or preparing shared data
- initializing shared resources needed by the test

### **Important points**

- `setup()` is **optional**
- It runs **once per test run**
- The value returned from `setup()` is passed to:
    - the `default()` function
    - the `teardown()` function

---

# **4. VU (Virtual User) Code Execution Phase**

This is the **main execution phase** of the test.

### **What happens here?**

The `default()` function is executed by each virtual user.

This is where you typically:

- send HTTP requests
- call APIs
- run checks/assertions
- simulate user behavior with `sleep()`
- perform the main load-testing actions

### **Important points**

- `default()` is the core of the test
- It is executed repeatedly depending on:
    - `vus`
    - `iterations`
    - `duration`
    - `stages`
- Each VU runs this function independently

---

# **5. Teardown Phase**

The **Teardown phase** runs **once after all VUs finish execution**.

### **What is it used for?**

Teardown is used for cleanup tasks such as:

- deleting test data
- revoking tokens
- releasing resources
- logging final cleanup information

### **Important points**

- `teardown()` is **optional**
- It runs **once after the test completes**
- It receives the same data returned by `setup()`

# **7. Explanation of the Code by Lifecycle Phase**

---

## **A. Init Phase**

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

export const options = {
	vus: 1,
	iterations: 1
};
```

### **What happens here?**

This code belongs to the **Init phase**.

It does the following:

- imports k6 modules
- defines the test configuration
- prepares the script before execution starts

### **Why is this Init?**

Because everything outside `setup()`, `default()`, and `teardown()` is part of the initialization phase.

---

## **B. Setup Phase**

```javascript
export function setup() {
	return { accessToken: "secret-token" };
}
```

### **What happens here?**

- `setup()` runs **once**
- it prepares some shared test data
- here it returns an object with an `accessToken`

### **What is returned from setup used for?**

The returned object is passed automatically to:

- `default(data)`
- `teardown(data)`

So in this example:

```javascript
{ accessToken: "secret-token" }
```

becomes available inside both `default()` and `teardown()` as `data`.

---

## **C. VU Execution Phase**

```javascript
export default function (data) {
	let res = http.get("https://test.k6.io");

	check(res, {
		"status is 200": (r) => r.status === 200
	});

	sleep(1);
}
```

### **What happens here?**

This is the actual test logic.

For every VU iteration:

1. A GET request is sent to `https://test.k6.io`
2. A check validates that the response status is `200`
3. The script sleeps for 1 second to simulate user think time

### **What is `data` here?**

`data` contains the object returned by `setup()`:

```javascript
{ accessToken: "secret-token" }
```

In this specific example, `data` is not used, but in real tests it could be used for:

- auth tokens
- shared IDs
- session data
- environment-specific test values

---

## **D. Teardown Phase**

```javascript
export function teardown(data) {
	console.log(`Cleaning up resources for token: ${data.accessToken}`);
}
```

### **What happens here?**

- `teardown()` runs once after the test ends
- it receives the same `data` returned by `setup()`
- it is used to clean up resources after execution

### **Example cleanup tasks**

- deleting created users/orders/test records
- revoking temporary access tokens
- removing uploaded test files
- printing final cleanup logs

---

# **8. Lifecycle Flow in Simple Order**

Here is the execution flow of a k6 script:

```text
1. Init phase
   ↓
2. setup() runs once
   ↓
3. default() runs repeatedly for each VU
   ↓
4. teardown() runs once after test completion
```

# **9. Important Notes About Lifecycle Phases**

## **Init**

- Required
- Runs first
- Used for imports, constants, options, helper functions

## **Setup**

- Optional
- Runs once before VUs
- Used for shared test preparation

## **VU / default()**

- Main execution phase
- Runs test logic repeatedly
- Used for HTTP requests, checks, and user simulation

## **Teardown**

- Optional
- Runs once after the test
- Used for cleanup

# **11. Key Takeaways**

- A k6 test script has **4 lifecycle phases**:
    1. Init
    2. Setup
    3. VU execution (`default()`)
    4. Teardown
- `setup()` and `teardown()` are optional
- `default()` is the main test execution function
- Data returned from `setup()` is passed to both `default()` and `teardown()`
- Use:
    - **Init** for configuration
    - **Setup** for preparing shared test data
    - **default()** for load generation
    - **Teardown** for cleanup
