## Why Checks Are Important

Checks help verify that the application is returning the **correct response** and behaving as expected under load.

They are useful for:

- Verifying response status codes
- Validating response times
- Checking response body content
- Identifying failures early during test execution
- Supporting automated pass/fail decisions in CI/CD pipelines

---

## 1. Basic Check Example

The following example sends a `GET` request and verifies that the response status is `200`.

```javascript
import http from "k6/http";
import { check } from "k6";

export default function () {
  let res = http.get("https://test-api.k6.io/public/crocodiles/1/");

  check(res, {
    "status is 200": (r) => r.status === 200,
  });
}
```

### Explanation

- `http.get()` sends a GET request to the given URL.
- `check()` validates the response.
- The first argument to `check()` is the response object.
- The second argument is an object containing one or more conditions.
- In this case, the condition checks whether `r.status === 200`.

If the condition evaluates to `true`, the check passes. Otherwise, it fails.

---

## 2. Multiple Checks in a Single Request

We can add more than one check to validate multiple aspects of the response.

For example:

- Check whether the status code is `200`    
- Check whether the response time is less than `500 ms`

```javascript
import http from "k6/http";
import { check } from "k6";

export default function () {
  let res = http.get("https://test-api.k6.io/public/crocodiles/1/");

  check(res, {
    "status is 200": (r) => r.status === 200,
    "response time is less than 500ms": (r) => r.timings.duration < 500,
  });

  console.log(`Complete Response Object: ${JSON.stringify(res, null, 2)}`);
}
```

### Explanation

This script performs two checks:

1. **Status code check**

```javascript
"status is 200": (r) => r.status === 200
```

2. **Response time check**`

```javascript
"response time is less than 500ms": (r) => r.timings.duration < 500
```


### Why print the response object?

The following line prints the complete response object:

```javascript
console.log(`Complete Response Object: ${JSON.stringify(res, null, 2)}`);
```

This is useful for understanding what data is available inside the response object, such as:

- `status`    
- `body`
- `headers`
- `timings`
- `cookies`

This makes it easier to write better checks.

## 3. Custom Check on Response Body - Failing Example

Checks are not limited to status codes and timings. We can also validate response content.

In the following example, we send a `POST` request with `"Hello World!"` and then check whether the response body contains `"Bonjour!"`.

Since the body does **not** contain `"Bonjour!"`, this check will fail.

```javascript
import http from "k6/http";
import { check } from "k6";

export default function () {
  let url = "https://httpbin.org/post";
  let res = http.post(url, "Hello World!");

  let result = check(res, {
    "Application says hello": (r) => r.body.includes("Bonjour!"),
  });

  if (result) {
    console.log(`Check success. Response body was: ${res.body}`);
  } else {
    console.log(`Check failed. Response body was: ${res.body}`);
  }
}
```

### Explanation

- A `POST` request is sent to `https://httpbin.org/post`    
- The request body is `"Hello World!"`
- The check looks for `"Bonjour!"` inside the response body
- Since `"Bonjour!"` is not present, the check fails
- `check()` returns `true` if all checks pass, otherwise `false`
- Based on that return value, we print a success or failure message

---

## 4. Custom Check on Response Body - Passing Example

Now let us update the condition to check for `"Hello World!"` instead.

Since that text is part of the request body and is reflected in the response, the check should pass.

```javascript
import http from "k6/http";
import { check } from "k6";

export default function () {
  let url = "https://httpbin.org/post";
  let res = http.post(url, "Hello World!");

  let result = check(res, {
    "Application says hello": (r) => r.body.includes("Hello World!"),
  });

  if (result) {
    console.log(`Check success. Response body was: ${res.body}`);
  } else {
    console.log(`Check failed. Response body was: ${res.body}`);
  }
}
```

### Explanation

- This time, the check looks for `"Hello World!"`    
- Since the response body contains that text, the check passes
- `result` becomes `true`
- The script enters the `if` block and prints the success message

---

## Important Note About `check()`

The `check()` function returns a boolean value:

- `true` → all checks passed    
- `false` → one or more checks failed

This is very useful when you want to add custom logic such as:

- printing extra debug information
- failing a pipeline step
- triggering alerts
- storing failed responses for investigation

## Common Use Cases for Checks

Checks can be used to validate many things, such as:

### Status code validation

```javascript
"status is 200": (r) => r.status === 200
```

### Response time validation

```javascript
"response time is < 500ms": (r) => r.timings.duration < 500
```

### Response body validation

```javascript
"body contains success": (r) => r.body.includes("success")
```

### JSON field validation

If the response is JSON:

```javascript
"username is correct": (r) => r.json().username === "john"
```

### Negative condition checks

For example, checking that an error message is **not** present:

```javascript
"no error message displayed": (r) => !r.body.includes("Internal Server Error")
```

This is especially useful when the application still returns a page, but that page contains an error due to backend failure.

---

## Practical Importance of Failed Checks

Sometimes an application may still return a response page successfully, but the content of that page may indicate a problem.

For example:

- The page loads, but contains an error message    
- An API returns `200 OK`, but the body contains failure details
- The application becomes slow under load and crosses expected response-time thresholds

Checks help detect such issues automatically.

---

## How Checks Help in CI/CD

Checks are extremely useful when integrating **k6** with CI/CD tools.

For example, if a check fails:

- the build can be marked as failed    
- deployment can be blocked
- alerts can be triggered
- test results can be reported automatically

This makes checks a key part of automated performance validation.
