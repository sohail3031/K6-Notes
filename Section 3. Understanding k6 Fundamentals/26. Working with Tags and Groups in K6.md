## 1. Introduction

In k6, **tags** and **groups** are powerful features that help organize, filter, and analyze performance test results more effectively.

They are especially useful in large test scripts where you want to:

- separate results by page, API, or scenario    
- organize user flows logically
- filter metrics for detailed analysis
- apply thresholds to specific requests or groups

---

# 2. Tags in K6

## What are Tags?

Tags in k6 are **key-value pairs** attached to metrics, requests, checks, or custom metrics.

They add **metadata** to your test results, making it easier to categorize and filter performance data.

### Example:

```javascript
tags: { name: "homepage" }
```

Here:

- `name` → tag key    
- `"homepage"` → tag value

---

## Why use Tags?

### 1. Filtering Metrics

Tags help you filter and categorize metrics, making it easier to focus on specific parts of your test.

### 2. Detailed Analysis

They allow more granular analysis, helping you identify issues related to specific scenarios, endpoints, or components.

### 3. Organizing Results

Tags help organize results when dealing with large and complex test scripts.

---

## Example: Using Tags in HTTP Requests

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

let params = {
	tags: { name: "homepage" }
};

export default function () {
	let res = http.get("https://test.k6.io/", params);
	let tags = params.tags;

	check(res, {
		[`status is 200 for ${tags.name}`]: (r) => r.status === 200,
		[`response time for ${tags.name} is below 200ms`]: (r) => r.timings.duration < 200
	});

	console.log(`Tags: ${JSON.stringify(tags)}, Status: ${res.status}`);

	sleep(1);
}
```

---

## Explanation

In this example:

- A tag named `homepage` is attached to the request.    
- The tag is used inside the `check()` messages to make the output more descriptive.
- The tag is also printed in the console log for easier debugging and reporting.

# 3. Groups in K6

## What are Groups?

Groups are used to **logically organize related requests or actions** into a named block.

They help structure your test script into meaningful user flows or application sections.

### Example use cases:

- Home page flow    
- Login flow
- Checkout flow
- Contact page flow 

---

## Why use Groups?

### 1. Organizing Tests

Groups help break a test into logical sections, making scripts easier to read and maintain.

### 2. Aggregating Metrics

k6 can report metrics for grouped requests separately.

### 3. Isolating Scenarios

Groups make it easier to identify which part of the application is slow or failing.

---

# 4. Example: Using `group()`

```javascript
import http from "k6/http";
import { check, group, sleep } from "k6";

export default function () {
	group("Home Page", function () {
		let res = http.get("https://test.k6.io/");

		check(res, {
			"status is 200": (r) => r.status === 200
		});

		sleep(1);
	});

	group("Contact Page", function () {
		let res = http.get("https://test.k6.io/contact");

		check(res, {
			"status is 200": (r) => r.status === 200
		});

		sleep(1);
	});
}
```

---

## Explanation

This script creates two groups:

- **Home Page**    
- **Contact Page**

Each group contains its own request and validation logic.

This makes the script easier to understand and helps k6 organize results by group.

---

# 5. Combining Tags and Groups

You can combine **tags** and **groups** to get even more structured and meaningful performance data.

- **Groups** organize test steps logically    
- **Tags** categorize requests and metrics within those groups

---

## Example: Using Tags + Groups + Custom Metrics

```javascript
import http from "k6/http";
import { check, group, sleep } from "k6";
import { Counter } from "k6/metrics";

let httpReqs = new Counter("http_reqs");

export default function () {
	group("Home Page", function () {
		let params = {
			tags: { name: "homePage" }
		};

		let res = http.get("https://test.k6.io/", params);
		let tags = params.tags;

		check(res, {
			[`status is 200 for ${tags.name}`]: (r) => r.status === 200
		});

		httpReqs.add(1, tags);

		sleep(1);
	});

	group("Contact Page", function () {
		let params = {
			tags: { name: "contactPage" }
		};

		let res = http.get("https://test.k6.io/contact", params);
		let tags = params.tags;

		check(res, {
			[`status is 200 for ${tags.name}`]: (r) => r.status === 200
		});

		httpReqs.add(1, tags);

		sleep(1);
	});
}
```

---

# 6. Explanation of the Combined Example

In this example:

## Group 1: Home Page

- A request is made to the home page    
- A tag `name: "homePage"` is attached
- A check verifies the response status
- A custom counter metric is incremented with the same tag

## Group 2: Contact Page

- A request is made to the contact page
- A tag `name: "contactPage"` is attached
- A check verifies the response status
- The same custom metric is incremented with a different tag

---

# 7. Benefits of Combining Tags and Groups

Using both together provides:

- **better organization** of scripts    
- **clear separation of user flows**
- **filtered metrics for specific pages or APIs**
- **improved debugging**
- **more meaningful reporting**

For example, you can quickly identify:

- whether the **Home Page** is slower than the **Contact Page**
- whether failures happen only in a specific group
- how many requests belong to each tagged section

# 8. Key Takeaways

## Tags

- Add metadata using key-value pairs    
- Help categorize, filter, and analyze metrics
- Can be used with requests, checks, and custom metrics

## Groups

- Organize related steps into logical blocks
- Improve script readability and reporting
- Help isolate performance issues by flow or feature

## Together

- Groups structure the test
- Tags classify the results
- Both together make analysis much easier in complex performance tests
