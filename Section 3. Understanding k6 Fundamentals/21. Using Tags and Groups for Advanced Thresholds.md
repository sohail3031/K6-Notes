# **1. Advanced Thresholds in k6**

Thresholds in k6 can be applied in more advanced ways than just checking a single metric. You can:

- Apply **multiple threshold conditions** to the same metric.    
- Apply thresholds to **different metrics together**.
- Apply thresholds to **specific groups**.
- Apply thresholds to **requests filtered by tags**.

This is useful when you want more control over performance validation for different parts of your test.

---

# **2. Combining Multiple Threshold Conditions**

You can define multiple threshold conditions for one or more metrics inside the `options.thresholds` object.

### Example:

- **Average response time** should be less than **200 ms**
- **90th percentile** response time should be less than **300 ms**
- **Maximum** response time should be less than **500 ms**
- **Failed request rate** should be less than **10%**

---

## **Code: Multiple thresholds together**

```javascript
import http from "k6/http";
import { check, sleep } from "k6";

export let options = {
	thresholds: {
		http_req_duration: ["avg<200", "p(90)<300", "max<500"],
		http_req_failed: ["rate<0.1"]
	},
	vus: 10,
	duration: "10s"
};

export default function() {
	let res = http.get("https://test-api.k6.io/public/crocodiles/1/");

	check(res, {
		"status is 200": (r) => r.status === 200
	});

	sleep(1);
}
```

---

## **Explanation**

In this script:

- `http_req_duration` has **three threshold conditions**:
    - `avg<200` → average response time must be less than 200 ms
    - `p(90)<300` → 90% of requests must complete within 300 ms
    - `max<500` → the slowest request must still be below 500 ms
- `http_req_failed: ["rate<0.1"]`
    - means **less than 10%** of HTTP requests should fail.

If **any one** of these thresholds is not met, the test is marked as **failed**.

# **3. Groups in k6**

A **group** is used to logically organize related actions or requests inside a test script.

Groups help you:

- Structure a script into meaningful sections or flows    
- Measure performance for a **specific part** of the script
- Apply thresholds to a **particular flow or block of requests** 

Groups are created using the `group()` function.

---

## **Code: Using `group()`**

```javascript
import http from "k6/http";
import { group } from "k6";

export let options = {
	thresholds: {
		"group_duration{group:::my_group}": ["avg<400"]
	},
	vus: 10,
	duration: "10s"
};

export default function() {
	group("my_group", function() {
		http.get("https://test-api.k6.io/public/crocodiles/1/");
	});
}
```

---

## **Explanation**

In this script:

- A group named **`my_group`** is created.
- The HTTP request inside that group becomes part of that group’s execution flow.
- The threshold:

```javascript
"group_duration{group:::my_group}": ["avg<400"]
```

means:

- Measure the **duration of the group `my_group`**
- Ensure the **average group duration** stays below **400 ms**

So this threshold is **not applied to the whole script**, but only to the code inside `my_group`.

# **4. Tags in k6**

**Tags** are key-value pairs attached to requests, checks, or custom metrics.

They help you:

- Categorize requests
- Filter metrics
- Apply thresholds only to specific requests

This is useful when you want to track different request types separately, such as:

- homepage requests
- login requests
- API requests
- static assets like CSS/JS/images

---

## **Code: Using tags**

```javascript
import http from "k6/http";

export let options = {
	thresholds: {
		"http_req_duration{staticAsset:true}": ["p(95)<300"]
	},
	vus: 10,
	duration: "10s"
};

export default function() {
	http.get("https://test-api.k6.io/static/some-file.js", {
		tags: { staticAsset: "true" }
	});
}
```

---

## **Explanation**

In this script:

- The request is tagged with:

```javascript
tags: { staticAsset: "true" }
```

- The threshold:

```javascript
"http_req_duration{staticAsset:true}": ["p(95)<300"]
```

means:

- Only consider requests where the tag `staticAsset=true`
- For those requests, **95% of response times** must be below **300 ms**

So if your script has multiple requests, but only some are tagged as static assets, the threshold applies **only to those tagged requests**.

# **5. Difference Between General Thresholds, Groups, and Tags**

## **A. General Threshold**

Applies to the **entire metric across all matching requests**.

Example:

```javascript
http_req_duration: ["avg<200"]
```

This checks the average duration of **all HTTP requests** in the test.

---

## **B. Group-Based Threshold**

Applies only to the code inside a **specific group**.

Example:

```javascript
"group_duration{group:::my_group}": ["avg<400"]
```

This checks only the duration of the group named `my_group`.

---

## **C. Tag-Based Threshold**

Applies only to requests or metrics with a **specific tag**.

Example:

```javascript
"http_req_duration{staticAsset:true}": ["p(95)<300"]
```

This checks only requests tagged with `staticAsset=true`.

---

# **6. Key Takeaways**

- **Thresholds** define pass/fail criteria for performance tests.
- You can apply **multiple threshold conditions** to the same metric.
- **Groups** help organize test flows and apply thresholds to specific sections of the script.
- **Tags** help categorize requests and apply thresholds only to selected requests.
- Advanced thresholds make performance tests more realistic and more useful in CI/CD pipelines.
