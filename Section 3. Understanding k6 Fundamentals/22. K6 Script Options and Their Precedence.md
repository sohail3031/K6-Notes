This lecture explains **where k6 configuration options can be defined** and how k6 decides which one to use when multiple sources are provided.

---

# **1. Ways to Set Options in k6**

k6 allows configuration from four main places:

1. **Default values (built-in)**    
2. **Config file**
3. **Script-level options (inside JS file)**
4. **Environment variables**
5. **CLI (Command Line Interface) flags**

Each of these has a **different priority level**.

---

# **2. Order of Precedence (Very Important)**

k6 resolves conflicts using this order:

```text
Lowest priority → Highest priority

1. Default values
2. Config file (--config)
3. Script options (options object in JS)
4. Environment variables (__ENV)
5. CLI flags (k6 run --vus, --duration, etc.)
```

### **Meaning:**

- If the same option is defined in multiple places, the **highest priority wins**
- CLI flags always override everything else

---

# **3. Default Configuration**

If you don’t provide any options, k6 uses default behavior:

- 1 Virtual User (VUs)
- 1 iteration or short default run
- Basic execution mode

### **Code (Default execution)**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export default function () {
	http.get("https://test.k6.io");
	sleep(1);
}
```

### **Explanation**

- No `options` object is defined    
- No CLI flags or env variables
- So k6 runs with **default settings**

---

# **4. Config File (External JSON Configuration)**

You can store configuration in a separate file and pass it during execution.

---

## **Config File Example**

```json
{
	"vus": 5,
	"duration": "10s",
	"thresholds": {
		"http_req_duration": ["avg<200", "p(90)<300", "max<500"]
	}
}
```

---

## **Run Command**

```bash
k6 run --config config.json script.js
```

---

## **Explanation**

- k6 loads config from external file
- Applies those settings before running script
- Useful for **environment-based configs (dev/staging/prod)**

---

# **5. Script-Level Options (Most Common)**

Options are defined inside the test script using `export const options`.

---

## **Code**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	vus: 5,
	duration: "10s",
	thresholds: {
		http_req_duration: ["avg<200", "p(90)<300", "max<500"]
	}
};

export default function () {
	http.get("https://test.k6.io");
	sleep(1);
}
```

---

## **Explanation**

- Options are defined inside the script
- Easy to version control (Git-friendly)
- Used as baseline configuration

---

# **6. Environment Variables (`__ENV`)**

k6 allows dynamic configuration using environment variables.

---

## **Code**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	vus: __ENV.K6_VUS || 10,
	duration: __ENV.K6_DURATION || "5s"
};

export default function () {
	http.get("https://test.k6.io");
	sleep(1);
}
```

---

## **Set Environment Variables**

```bash
export K6_VUS=5
export K6_DURATION=10s
```

---

## **Run**

```bash
k6 run script.js
```

---

## **Explanation**

- Uses system-level variables
- Very useful for:
    - CI/CD pipelines
    - Docker containers
    - Multi-environment testing

---

# **7. CLI Flags (Highest Priority)**

CLI flags override everything else.

---

## **Code**

```javascript
import http from "k6/http";
import { sleep } from "k6";

export const options = {
	vus: 5
};

export default function () {
	http.get("https://test.k6.io");
	sleep(1);
}
```

---

## **Run Command**

```bash
k6 run --vus 10 --duration 10s script.js
```

---

## **Explanation**

- Even though script sets `vus: 5`
- CLI sets `--vus 10`
- Final result = **10 VUs (CLI wins)**

---

# **8. How Precedence Works (Real Example)**

If all are defined:

| Source      | vus |
| ----------- | --- |
| Default     | 1   |
| Config file | 5   |
| Script      | 10  |
| ENV         | 15  |
| CLI         | 20  |

👉 Final value used = **20 (CLI wins)**

---

# **9. Key Takeaways**

- k6 allows multiple ways to configure test behavior
- Priority order is critical for debugging unexpected behavior
- CLI flags always override everything
- ENV variables are best for CI/CD flexibility
- Script options are best for version control
- Config files are useful for environment separation

---

# **10. Interview / Exam Summary**

- **Highest precedence:** CLI flags
- **Lowest precedence:** Default values
- `__ENV` is used for environment variables
- `options` object is inside script
- `--config` loads external JSON config
- k6 resolves conflicts using strict hierarchy
