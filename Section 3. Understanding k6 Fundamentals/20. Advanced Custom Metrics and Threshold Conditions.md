In this lecture, the focus is on applying **thresholds to custom metrics** in **k6**.  
Earlier, you used thresholds with built-in metrics like `http_req_duration`; now the same idea is extended to **custom metrics** such as:

- **Counter**    
- **Rate**
- **Trend**

Thresholds let you decide whether your test should **pass or fail** based on the values collected by these custom metrics.

---

# 1) Thresholds on Custom Metrics

A **custom metric threshold** works exactly like a built-in metric threshold:

- you create a custom metric    
- collect values during the test
- define threshold conditions in `options.thresholds`
- k6 evaluates those conditions and marks the test **pass/fail**

---

# 2) Counter Threshold Example

## Code

```javascript
import { Counter } from "k6/metrics";
import { sleep } from "k6";

let myCounter = new Counter("my_counter");

export let options = {
	thresholds: {
		my_counter: ["count>100"]
	},
	vus: 1,
	duration: "10s"
};

export default function() {
	myCounter.add(1); // increment counter by 1 in each iteration
	sleep(0.1);
}
```

---

# 3) Explanation of Counter Threshold Example

## Custom metric

```javascript
let myCounter = new Counter("my_counter");
```

This creates a **Counter metric** named `my_counter`.

A **Counter** is used to **count occurrences of an event**.

In this script, every iteration does:

```javascript
myCounter.add(1);
```

So the counter increases by **1 on each iteration**.

---

## Threshold

```javascript
thresholds: {
	my_counter: ["count>100"]
}
```

This means:

> The **final total count** of `my_counter` must be **greater than 100**

---

## Test execution settings

```javascript
vus: 1,
duration: "10s"
```

This means:

- **1 virtual user**    
- test runs for **10 seconds**

Since the script sleeps for `0.1` seconds in every iteration, k6 will run the function repeatedly for 10 seconds and keep incrementing the counter.

---

## What determines pass/fail?

- If the counter value becomes **more than 100** within 10 seconds → **threshold passes**    
- If it stays **100 or below** → **threshold fails**

---

# 4) Rate Threshold Example

## Code

```javascript
import http from "k6/http";
import { Rate } from "k6/metrics";
import { sleep } from "k6";

let myRate = new Rate("my_rate");

export let options = {
	thresholds: {
		my_rate: ["rate>0.95"]
	},
	vus: 1,
	duration: "10s"
};

export default function() {
	let res = http.get("https://test-api.k6.io/public/crocodiles/1/");
	
	myRate.add(res.status === 200);
	
	sleep(0.1);
}
```

---

# 5) Explanation of Rate Threshold Example

## Custom metric

```javascript
let myRate = new Rate("my_rate");
```

A **Rate** metric measures the **proportion of successful events**.

---

## Adding values to the rate

```javascript
myRate.add(res.status === 200);
```

This expression returns:

- `true` if response status is `200`    
- `false` otherwise

A `Rate` metric tracks the ratio of `true` values.

So this line is effectively measuring:

> **How many requests were successful out of all requests**

---

## Threshold

```javascript
my_rate: ["rate>0.95"]
```

This means:

> More than **95%** of the recorded events must be successful

---

## Pass/fail meaning

- If the success rate is **above 95%** → threshold passes    
- If the success rate is **95% or below** → threshold fails

For example:

- 98 successful out of 100 → `0.98` → pass
- 90 successful out of 100 → `0.90` → fail

---

# 6) Trend Threshold Example

## Code

```javascript
import http from "k6/http";
import { Trend } from "k6/metrics";
import { sleep } from "k6";

let myTrend = new Trend("my_trend");

export let options = {
	thresholds: {
		my_trend: ["p(95)<300"]
	},
	vus: 1,
	duration: "10s"
};

export default function() {
	let res = http.get("https://test-api.k6.io/public/crocodiles/1/");
	
	myTrend.add(res.timings.duration);
	
	sleep(0.1);
}
```

---

# 7) Explanation of Trend Threshold Example

## Custom metric

```javascript
let myTrend = new Trend("my_trend");
```

A **Trend** metric stores numeric values over time and lets you analyze:

- average    
- minimum
- maximum
- percentiles like `p(90)` and `p(95)`

---

## Adding values to the trend

```javascript
myTrend.add(res.timings.duration);
```

This stores the **response duration** of each request inside the trend metric.

So `my_trend` becomes a custom collection of response times.

---

## Threshold

```javascript
my_trend: ["p(95)<300"]
```

This means:

> 95% of the values stored in `my_trend` must be **less than 300 ms**

---

## Pass/fail meaning

- If the **95th percentile** response time is below **300 ms** → pass    
- Otherwise → fail

This is useful when you want to ensure **almost all requests stay fast**, not just the average.

---

# 8) Key Idea Behind These Examples

The lecture is showing that **custom metrics can have their own thresholds**, just like built-in metrics.

So you can define performance rules for:

- **Counter** → total number of events    
- **Rate** → success ratio / failure ratio
- **Trend** → latency or timing distributions
- **Gauge** → latest/current value

---

# 9) Important Notes and Clarifications

## A) `count>100` for Counter

This checks the **final accumulated count** of the counter metric.

It does **not** mean “100 per second” or “100 per VU”.  
It means the total recorded count at the end of the test should be greater than 100.

---

## B) `rate>0.95` for Rate

A `Rate` metric stores the fraction of times a condition was true.

So:

```javascript
myRate.add(res.status === 200);
```

means:

- success contributes `true`
- failure contributes `false`

At the end, k6 calculates the overall success ratio.

---

## C) `p(95)<300` for Trend

This is not checking every request individually.  
It checks the **95th percentile of all recorded trend values**.

That means:

- 95% of recorded values must be below 300 ms
- a few slow requests are allowed, but too many slow ones will fail the threshold

---

# 10) What about Gauge Thresholds?

This lecture didn’t include a **Gauge** threshold example, but yes — **Gauge metrics can also have thresholds**.

A `Gauge` stores the **latest/current value** added to it, and you can apply thresholds like:

```javascript
response_time_gauge: ["value<500"]
```

This would mean the gauge value should remain below `500`.

---

# 11) Summary

## Counter threshold

```javascript
my_counter: ["count>100"]
```

- Passes if the counter total is more than 100    

## Rate threshold

```javascript
my_rate: ["rate>0.95"]
```

- Passes if more than 95% of events are successful

## Trend threshold

```javascript
my_trend: ["p(95)<300"]
```

- Passes if 95% of recorded trend values are below 300 ms    

---

# 12) Clean takeaway

Thresholds on custom metrics allow you to create **application-specific performance rules**.

That means you’re not limited to built-in metrics like `http_req_duration`.  
You can create your own metrics and define success criteria such as:

- number of successful operations    
- acceptable response-time trends
- required success rate
- current resource-related values
