Thresholds in **k6** define **pass/fail performance criteria** for your test.  
Unlike `check()`, which validates responses **during each iteration**, **thresholds are evaluated against collected metrics and determine whether the overall test passes or fails**.

---

# 1) What are Thresholds?

A **threshold** is a rule you attach to a metric, such as:

- average response time    
- 90th/95th percentile response time
- maximum response time
- failure rate
- custom metric values

If the metric does **not** satisfy the threshold, the **test is marked as failed**.

---

# 2) Why use Thresholds?

Thresholds are important because they give you **clear performance goals**.

## Benefits of thresholds

1. **Pass/fail criteria**    
    - You can automatically decide whether the application performance is acceptable.
2. **Automation-friendly**
    - Very useful in **CI/CD pipelines** because the build/test can fail automatically if performance degrades.
3. **Regression detection**
    - If a new code change slows the app down, thresholds help catch that immediately.

---

# 3) Basic Threshold Example

## Code

```javascript
import http from "k6/http";
import { sleep } from "k6";

export let options = {
	thresholds: {
		http_req_duration: ["p(95)<500"] // 95% of requests must complete in under 500ms
	}
};

export default function() {
	http.get("https://test-api.k6.io/public/crocodiles/1/");
	sleep(1);
}
```

---

# 4) Explanation of the First Example

## `thresholds`

This section is used to define performance conditions for metrics.

```javascript
thresholds: {
	http_req_duration: ["p(95)<500"]
}
```

### `http_req_duration`

- This is a **built-in k6 metric**
- It represents the **total HTTP request time**
- It includes:
    - sending the request
    - waiting for the server
    - receiving the response

### `p(95)<500`

This means:

> **95% of all HTTP requests should complete in less than 500 ms**

So if the 95th percentile of `http_req_duration` is below 500 ms, the threshold passes.

# 5) Second Example: Multiple Threshold Conditions

## Code

```javascript
import http from "k6/http";
import { sleep, check } from "k6";

export let options = {
	thresholds: {
		http_req_duration: ["avg<200", "p(90)<300", "max<500"]
	}
};

export default function() {
	let res = http.get("https://test-api.k6.io/public/crocodiles/1/");
	
	check(res, {
		"status is 200": (r) => r.status === 200
	});
	
	sleep(1);
}
```

---

# 6) Explanation of the Second Example

Here we are applying **multiple threshold conditions** to the same metric: `http_req_duration`.

## Threshold conditions used

### 1. `avg<200`

- The **average response time** of all HTTP requests must be less than **200 ms**    

### 2. `p(90)<300`

- **90% of requests** must complete in less than **300 ms**

### 3. `max<500`

- The **slowest request** must still complete in less than **500 ms**

---

# 7) Important Difference: `check()` vs `thresholds`

This part is important because your last explanation said:

> “It’s possible to add multiple values in a single check condition.”

That is **not correct for this example**.  
This example is about **multiple threshold rules**, not multiple check values.

## `check()`

- Validates conditions **during each iteration/request**
- Used for correctness checks like:
    - status code is 200
    - response contains expected text
    - response time for that specific request is under a limit

Example:

```javascript
check(res, {
	"status is 200": (r) => r.status === 200
});
```

## `thresholds`

- Validates **aggregated performance metrics** after/during the test run
- Used for performance criteria like:
    - average response time
    - percentile response times
    - failure rate
    - custom metrics

---

# 8) Corrected Explanation for the Second Example

A better explanation for your second script would be:

> The script defines **multiple threshold conditions** for the built-in metric `http_req_duration`.  
> k6 will verify whether:
> 
> - the **average** response time is below **200 ms**
> - **90%** of requests finish below **300 ms**
> - the **maximum** response time stays below **500 ms**
> 
> If **any one** of these threshold conditions fails, the **test is considered failed**.

---

# 9) Summary

## Thresholds in k6

- are used to define **performance expectations**    
- provide **pass/fail rules** for your performance test
- are usually defined inside the `options` object
- can be used with:
    - **built-in metrics** like `http_req_duration`
    - **custom metrics** like `Rate`, `Counter`, `Trend`, `Gauge`

## In your examples

- **Example 1** checks if **95% of requests** complete within **500 ms**
- **Example 2** checks **average**, **90th percentile**, and **maximum** response time conditions together
