Execution context variables in **k6** provide useful information about the **current virtual user (VU)**, the **scenario**, the **test run**, and the **instance** executing the script. These variables are very helpful when you want to make your tests more dynamic and realistic.

For example, execution context variables can help you:

- Run different logic for different VUs    
- Use different test data for each VU or iteration
- Track the current iteration number
- Identify which scenario is currently running
- Understand the overall state of the test execution

k6 provides these details through the **`k6/execution`** module.

---

# Why Use Execution Context Variables?

Execution context variables are useful when you want to:

1. **Run different logic for different VUs**  
    For example, VU 1 can execute one user flow while VU 2 executes another.    
2. **Use different data for each VU and iteration**  
    This is useful in data-driven testing where each VU should use unique input data.
3. **Understand the current execution state**  
    You can know which scenario is running, how many iterations are completed, and how many VUs are active.
4. **Debug test behavior**  
    Logging execution context details makes it easier to identify where and why a failure happened.

---

# The `k6/execution` Module

To access execution context variables, import the execution module:

```javascript
import exec from "k6/execution";
```

The `exec` object provides information in the following categories:

- **`exec.instance`** → information about the current k6 instance    
- **`exec.scenario`** → information about the currently running scenario
- **`exec.test`** → information about the overall test
- **`exec.vu`** → information about the current virtual user

---

# Code Example

```javascript
import exec from "k6/execution";

export default function () {
	console.log(`Execution context

	Instance info
	-------------
	VUs active: ${exec.instance.vusActive}
	Iterations completed: ${exec.instance.iterationsCompleted}
	Iterations interrupted: ${exec.instance.iterationsInterrupted}
	VUs initialized: ${exec.instance.vusInitialized}
	Time passed from start of run (ms): ${exec.instance.currentTestRunDuration}

	Scenario info
	-------------
	Name of the running scenario: ${exec.scenario.name}
	Executor type: ${exec.scenario.executor}
	Scenario start timestamp: ${exec.scenario.startTime}
	Percentage complete: ${exec.scenario.progress}
	Iteration in instance: ${exec.scenario.iterationInInstance}
	Iteration in test: ${exec.scenario.iterationInTest}

	Test info
	---------
	All test options: ${JSON.stringify(exec.test.options)}

	VU info
	-------
	Iteration in instance: ${exec.vu.iterationInInstance}
	Iteration in scenario: ${exec.vu.iterationInScenario}
	VU ID in instance: ${exec.vu.idInInstance}
	VU ID in test: ${exec.vu.idInTest}
	VU tags: ${JSON.stringify(exec.vu.tags)}
	`);
}
```

# Explanation of Execution Context Variables

## 1. `exec.instance`

This provides information about the **current k6 instance**.

### Common properties:

- **`exec.instance.vusActive`**  
    Number of currently active VUs in this instance.    
- **`exec.instance.vusInitialized`**  
    Number of VUs initialized in this instance.
- **`exec.instance.iterationsCompleted`**  
    Total number of iterations completed in this instance.
- **`exec.instance.iterationsInterrupted`**  
    Number of interrupted iterations in this instance.
- **`exec.instance.currentTestRunDuration`**  
    Time elapsed since the test started, in milliseconds.

---

## 2. `exec.scenario`

This provides information about the **currently running scenario**.

### Common properties:

- **`exec.scenario.name`**  
    Name of the current scenario.
- **`exec.scenario.executor`**  
    Type of executor being used, such as `constant-vus`, `ramping-vus`, etc.
- **`exec.scenario.startTime`**  
    Timestamp when the scenario started.
- **`exec.scenario.progress`**  
    Percentage of scenario completion.
- **`exec.scenario.iterationInInstance`**  
    Current iteration number for the scenario within the current instance.
- **`exec.scenario.iterationInTest`**  
    Current iteration number for the scenario across the whole test.

---

## 3. `exec.test`

This provides information about the **overall test execution**.

### Common property:

- **`exec.test.options`**  
    Gives access to the test options currently being used.

This is useful for debugging and verifying which configuration is active during execution.

---

## 4. `exec.vu`

This provides information about the **current virtual user**.

### Common properties:

- **`exec.vu.iterationInInstance`**  
    Current iteration number of this VU within the instance.
- **`exec.vu.iterationInScenario`**  
    Current iteration number of this VU within the scenario.
- **`exec.vu.idInInstance`**  
    Unique ID of the VU within the current instance.
- **`exec.vu.idInTest`**  
    Unique ID of the VU across the entire test.
- **`exec.vu.tags`**  
    Tags associated with the current VU.

# Sample Use Cases

## 1. Use different test data for each VU

```javascript
import exec from "k6/execution";

export default function () {
	const userId = exec.vu.idInTest;
	console.log(`Using test data for user ${userId}`);
}
```

---

## 2. Run logic based on iteration number

```javascript
import exec from "k6/execution";

export default function () {
	if (exec.vu.iterationInScenario === 0) {
		console.log("This is the first iteration for this VU.");
	}
}
```

---

## 3. Print the current scenario name

```javascript
import exec from "k6/execution";

export default function () {
	console.log(`Running scenario: ${exec.scenario.name}`);
}
```

# Key Takeaways

- The **`k6/execution`** module gives you detailed information about the **instance**, **scenario**, **test**, and **VU**.    
- These variables are very useful for:
    - data-driven testing
    - debugging
    - running different logic for different VUs
    - tracking iterations and scenario progress
- Execution context variables help make your performance tests more **dynamic**, **realistic**, and **easier to analyze**.

# Final Note

Execution context variables are especially useful when you start working with:

- multiple scenarios    
- different datasets for different VUs
- custom logging and debugging
- advanced performance testing workflows

As your k6 scripts become more advanced, the **`k6/execution`** module becomes an important tool for controlling and understanding test execution.
